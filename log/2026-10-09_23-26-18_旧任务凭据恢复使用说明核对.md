# 旧任务凭据恢复使用说明核对 · 2026-10-09 23:26:18

本次为功能解释请求，无业务代码修改、无模型调用、无任务启动。已读取最近修复日志并核对 App.tsx、modelConfig.ts、storage.ts、ReviewPanel.tsx 及 web/app.py 的实际请求处理。

- 显示条件是已选择任务且 `model_config_origin !== v2`。「旧任务」表示旧版单一 Key/Base 配置方式，不能按创建日期判断。
- 用户先从任务记录选中任务，再补填有权访问任务原模型的 API Key 和对应的兼容 API Base。该表单没有保存按钮，继续准备、重做配音视频或审核阶段执行时由 taskModelPayload 携带凭据。
- 新版 v2 请求只携带 model_config/voice，凭据从分环节连接获取；旧任务凭据输入不影响新版草稿。填凭据不会自动更换任务模型或修复字体/素材错误。
- Key 不保存在浏览器持久存储，页面刷新后需重填。点击「清空本次凭据」只清当前页面两个输入，不撤销平台 Key，不取消已提交任务，也不清除服务端运行任务的内存凭据。
- 后端按任务 ID 在 _JOB_KEYS 中暂存执行凭据，不写任务配置；服务重启会失去该内存。用户提交继续动作后，刷新页面不会使正在执行的任务立即失去已提交凭据。
- 注意旧 storage 模块还会读取迁移前曾保存的 API Base，因此不能将「刷新即清空」扩大解释成所有旧 Base 的持久记录也必然消失。本次仅解释当前功能，未修改兼容迁移逻辑。

已向用户说明两字段含义、操作步骤，以及 Key/Base 必须属于同一个模型服务。原有未提交的项目文件保持原样。本次没有需要执行的代码冒烟测试，核对依据为表单事件和前后端请求路径。
