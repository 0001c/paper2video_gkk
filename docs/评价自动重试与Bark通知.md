# 评价自动重试与 Bark 通知

2026-10-13 验收完成。针对成片逐页评价因输出格式、证据引用或短暂网络异常而中断的问题，失败页自动重试；完成、最终异常及等待审核可以通过 Bark 提醒。

## 使用

页面任务导航下方新增折叠卡片 **Bark 任务通知**，在新建任务、任务详情、任务记录页面均可打开。填写 Bark App 提供的完整推送地址，选择通知事件，保存后可发送测试通知。留空保存会保留原地址；修改未保存时不能发送测试，避免误用旧配置。

这是本机全局配置，适用于之后运行或重新评价的任务。默认关闭；本次已按用户提供的地址开启完成、失败、等待审核三类通知。配置保存和服务启动不补发历史通知。测试成功表示 Bark 服务确认接收，需要用户在手机上确认实际展示。

## 自动重试的范围

- 每页首次请求加最多两次自动重试，总计最多三次。输出缺维度、错误时间引用、无材料依据的配音引文等校验失败，会提供具体原因和本页允许的抽帧时间，让模型重新评价。
- HTTP 429、500、502、503、504，及连接或超时异常进行有界退避重试。鉴权错误和 token 截断不进行无意义的同预算重试。
- 成功页缓存、知识问答和实际音轨证据复用。整页全部所选检查通过结构校验后才发布，失败尝试不会产生重复页分。
- 仅将 `"2.963"` 这种纯十进制数值表示转换为数字，再按原来的误差范围严格核对真实抽帧时间。不会猜时间、吸附到邻近帧、删问题或改评分。
- 三次仍失败时保留模型诊断、成片与已完成页，进入等待处理，按通知配置推送最终异常。材料缺失、时间轴不一致等前置错误需要修正材料。
- 输出格式重试与知识不足触发的自动重写是两套机制；格式异常不会触发讲稿重写、配音或合片。各项通过门槛保持原值，评分规则版本仍为 3，不让有效历史缓存失效。

失败尝试保存在结果目录的 `evaluation/rubric-…-page-N-attempt-….json`；通过校验的页保存在 `rubric-…-page-N.json`。每次重试和完成页都会写入任务运行日志。分项评价日志分别列出知识、PPT、呈现和配音的分数与通过线，最低项分数不再冒充知识答题百分比。

## 通知行为和存储

正常完成发送完成通知；生成失败或评价异常发送需要处理通知；正常进入人工审核发送等待审核通知。中间逐页重试和已创建自动续跑子任务的父任务不单独推送，取消的任务不推送。同一任务的同一结果按指纹去重，重新评价得到不同结果时可以再次通知。

推送只包含任务编号和通用状态，不包含课文、讲稿、模型密钥或错误原文。完整地址使用当前 Windows 账户 DPAPI 加密，保存至 Git 忽略的 `.local/credentials/bark.dpapi`；浏览器和公开配置接口只显示服务地址，不回显设备 Key。当前持久化实现依赖 Windows。

网络发送在后台线程执行，连接/读取超时分别为 3/5 秒，禁止重定向。发送失败只记录通知状态，不改变任务分数、产物或队列最终清理。网络结果可能不确定，通知请求不自动重复发送；应用去重不等于保证手机恰好收到一次。终态事件流可能先于通知请求结束关闭，通知失败提示可以通过重新读取任务详情查看。

实现依据：[Bark 官方 API 文档](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)。使用 JSON `POST /push`，设备 Key 放在请求体中。
