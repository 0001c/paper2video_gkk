# 音色方案：MiMo-V2.5-TTS 生成参考音色 + 上传自定义音色

> 依据：小米 MiMo 官方文档（语音合成 MiMo-V2.5-TTS 系列，页面更新于 2026-07-15）
> 与本项目 `wei_utils` / `speech_gen.py` / `language_config.py` 的实际约束。
> 结论先行：**方案可行且推荐，但要用"生成参考音色"而不是"逐页调用云端 TTS"**。

---

## 一、我的评价（结论）

**推荐接入，但接的方式要改一处。** 你的思路（提示词生成音色 + 保留上传 + 二选一的前端）完全成立，
唯一要调整的是**它挂在哪一环**：

| 接法 | 每任务调用 | 逐页合成 | 评价 |
|---|---|---|---|
| A. 用 MiMo 直接逐页合成讲稿 | 14 次（14 页） | 云端 | ✗ 与"本地化"原则冲突，限时免费不可依赖，还会改动字幕对齐链路 |
| **B. 用 MiMo 生成一段"音色样本"，逐页仍走本地 Qwen3-TTS 克隆** | **1 次** | **本地** | ✅ **推荐** |

选 B 的四个理由（都是本项目的硬约束，不是偏好）：

1. **一致性**：音色只定一次，全片 14 页必然同一个人声；逐页调用云端反而可能页间漂移。
2. **本地化/可离线**：逐页合成仍由本地 Qwen3-TTS 完成，云端只在"造音色"时用一次；
   免费期结束、断网、无 key 时，默认链路（内置参考音频）**完全不受影响**。
3. **链路不动**：字幕是本地 TTS 的 wav + 本地 ForcedAligner 对齐出来的；
   换成云端 TTS 就要重做对齐、时长估计、逐句切分，风险和收益不成比例。
4. **参考文本可控**：我们把要朗读的文本**自己给定**，于是它就是标准的 `ref_text`，
   **绕开 ASR 转写**（本项目实测 Qwen3-ASR 对参考音频会转出错文本，而错误的 ref_text
   会直接拉低克隆保真度 —— 见 `language_config.py:_sibling_ref_text` 的注释）。

**一个必须写进设计的前提**：文档写明计费是"**限时免费**"。
所以它只能当**可选增强**，绝不能成为唯一路径 —— 否则免费期一结束，界面上的"生成音色"
就变成一个纯报错的按钮。必须有回落（见第四节）。

## 二、核实到的接口事实

来自官方文档（不是推测）：

- **OpenAI 兼容**：`base_url = https://api.xiaomimimo.com/v1`，用官方 `openai` SDK 的
  `client.chat.completions.create(...)`；音频以 base64 放在 `choices[0].message.audio.data`。
- **三个模型，能力互斥**（同一次调用只能用其中一个）：

  | 模型 | 能力 | 说明 |
  |---|---|---|
  | `mimo-v2.5-tts` | 预置音色 | 8 个精品音色，**支持唱歌**，不支持音色设计/复刻 |
  | `mimo-v2.5-tts-voicedesign` | 文本描述设计音色 | `user` 消息**就是音色描述**，可不传待合成文本 |
  | `mimo-v2.5-tts-voiceclone` | 音频样本复刻 | 样本 base64（`data:audio/mpeg;base64,...`），≤10 MB，仅 mp3/wav |

- **预置音色清单**（这一条直接把"男女音色"这个需求解决了，**不需要任何种子素材**）：

  | 音色 | 语言 | 性别 |
  |---|---|---|
  | 冰糖 / 茉莉 | 中文 | 女 |
  | 苏打 / 白桦 | 中文 | 男 |
  | Mia / Chloe | 英文 | 女 |
  | Milo / Dean | 英文 | 男 |

  ⚠️ `mimo_default` 是"因集群而异"的（中国集群默认冰糖，其他集群默认 Mia）——
  **我们不用它**，一律显式指定音色名，避免同一份配置在不同部署上出不同音色。

- **输出**：`audio={"format": "wav"}`（非流式）；流式要求用 `pcm16`，且官方示例给出
  **24 kHz / 单声道** 的 PCM16LE。
- **风格控制**两种：自然语言（放 `user`）、音频标签（放 `assistant` 文本里，如 `(严肃)`、`(磁性)`）。
- **计费**：**限时免费**。

## 三、推荐架构（B 方案）

```
用户选择音色 ──┬─ 预置音色（苏打/冰糖/…）        ┐
               ├─ 提示词设计（voicedesign）      ├─► MiMo 生成一段 8~15 秒参考音频
               └─ 上传自己的音频（voiceclone 不需要）┘        + 我们给定的同名 .txt（ref_text）
                                                            │
                                                            ▼
                          缓存到 jobs/_voices/<sha1>.wav|.txt（同一音色只生成一次）
                                                            │
                                                            ▼
                       --ref_audio / --ref_text ──► 本地 Qwen3-TTS 逐页克隆合成
```

### 三个关键设计点

**① 参考文本必须由我们给定，`optimize_text_preview` 要关掉**

文档说 `voicedesign` 模型可以设 `optimize_text_preview=True` 从而不用传 `assistant` 文本
（由模型自动润色生成）。**对我们不合适**：那样我们不知道模型实际念了什么，
`ref_text` 就失控了，只能回头去让 Qwen3-ASR 转写 —— 正好掉进上面说的那个坑。

所以固定用法是：

```python
messages = [
    {"role": "user", "content": "<场景与风格指令>"},
    {"role": "assistant", "content": REF_TEXT[script_lang]},   # 我们给定，就是 ref_text
]
audio = {"format": "wav", "voice": ...}   # 预置音色才传 voice
```

参考文本用**中性学术讲解句**（约 8~15 秒读长），中英各一条。理由：文档明确说
"合成文本要贴合音色"，给"温柔治愈系女声"配一段晚安独白效果最好 —— 反过来说，
拿一段和用途无关的极端文本（如文档里的情绪化例句）去造音色，得到的音色会偏离
"论文讲解"这个使用场景。

**② 预置音色按讲稿语言过滤**

中文讲稿 → 只用中文预置音色（冰糖/茉莉/苏打/白桦）；
英文讲稿 → 只用英文预置音色（Mia/Chloe/Milo/Dean）。
不这么做就会出现"英文样本克隆中文"的跨语言克隆（本项目验证过这条路可行 ——
`zeyu_zh.wav` 就是这么造的 —— 但音色和发音都会打折扣，不该作为默认选项）。

**③ 设计音色必须"试听 + 重掷 + 存下来"**

同一段描述两次生成结果**不完全相同**（音频生成都有随机性）。所以三件事缺一不可：

- **试听**：生成后立刻能听（这也是它比"上传"更好用的地方）；
- **重掷**：不满意就再生成一次，不消耗用户成本（限时免费）；
- **保存**：满意的结果落进缓存，之后所有任务复用同一份 wav → **音色稳定**。
  不保存的话，"同一个音色"在两次任务里会是两个人声，这比没有选择更糟。

## 四、回落与失败处理（决定了这个功能是"增强"还是"新故障点"）

按优先级回落，**每一级都要在界面上说明当前用的是哪一级**：

```
① 用户上传的参考音频（有就用，最高优先）
② 选中的预置/设计音色 → 缓存命中 → 直接用（不再调 API）
③ 缓存未命中 → 调 MiMo 生成 → 成功则缓存
④ MiMo 不可用（无 key / 免费期结束 / 网络失败 / 限流）→ 回落到内置本地参考音频，
   并在界面上写明"已回落到内置音色" + 原因，**不阻断任务**
```

默认值就是第 ④ 级（也就是现在的行为：`zeyu.wav` / `zeyu_zh.wav`），
所以**不改配置的现有流程一个字都不变** —— 这是这次改动"零回归"的保证。

另外两条：

- **key 放哪**：建议放服务端的 `.env`（`MIMO_API_KEY`），与使用者自己的 DeepSeek key 分开。
  理由：`限时免费` 的 key 共享一份最简单，也不用每个使用者去申请（这与"API key 存浏览器本地"
  那件事不冲突：那是使用者自己付费的凭据，这个是服务端的免费配额）。
  ⚠️ **单人使用也可以放浏览器本地**，二选一，需要你定。
- **隐私**：只把一段**固定中性句**发给第三方，**不发送论文正文、幻灯片、讲稿**。
  这是这条链路唯一的外部数据出口，要写进 README。

## 五、前端设计（对你的方案的评估）

你的想法是对的 —— **和「论文类型」一样用单选切换，选哪个就出哪套控件**。
这是本项目已有的交互模式（`RadioGroup` + 条件渲染），复用它能省掉一次设计成本，
也让使用者只需学一次。

我建议把**二选一改成三选一**：

```
音色
( ) 使用默认音色（内置本地参考音频，零依赖 —— 默认项）
( ) 预置音色      →  下拉：冰糖(女·中文) / 苏打(男·中文) / 茉莉(女·中文) / 白桦(男·中文)
                      （讲稿是英文时自动切换成英文那组）
( ) 提示词设计    →  文本框：描述你想要的音色（1~4 句）
                      [生成试听]  [重新生成]  [保存为我的音色]
( ) 上传音频      →  拖放/选择文件 + （可选）参考文本输入框
                      校验：格式按文件头 / 时长 3~30 秒 / 采样率与声道只警告
```

三点补充建议：

1. **默认项必须是"不接云端"**。放进选项列表里，让"离线可用"这件事一眼可见，
   而不是藏在文档里。
2. **描述框要给例子**（否则使用者写不出有效的描述）。文档给的关键维度可以压成一行提示：
   `性别年龄 + 音色质感 + 语速节奏 +（可选）角色/场景`，
   例如「三十多岁的女性学者，音色清亮而稳，语速适中，像在讲台上讲课」。
3. **上传与设计可以并存**：使用者可以先"设计"一个满意的音色，然后**把它下载下来**，
   以后改用"上传"路径使用 —— 这样即使免费期结束，他已经攒下的音色资产仍然能用。
   这一条价值很高，成本只是一个下载链接。

## 七、实施记录（2026-09-19 已完成）

**已定的两个问题**（原本在下面第八节等你确认）：`MIMO_API_KEY` 放**服务端 `.env`**；
参考文本由我定 —— 已写进 `scripts/mimo_voice.py` 的 `REF_TEXTS`，中英各一句中性学术开场白。

**实测数据**（全部来自真实调用，不是抄文档）：

| 项 | 实测结果 |
|---|---|
| 调用方式 | OpenAI 兼容：`chat.completions.create(model=…, messages=…, audio={"format":"wav",…})`；音频 base64 在 `message.audio.data` |
| 输出格式 | **24 kHz 单声道 WAV**（与文档的 24k PCM16 一致） |
| 时长 / 延迟 | 预置音色 13.6~16.3 秒 / 3.4~5.0 秒；描述设计 12.3~20.8 秒 / 2.7~5.6 秒 |
| 三个模型 | 全部可调通：`mimo-v2.5-tts`（预置）、`-voicedesign`（描述设计） |
| **克隆验证** | 用生成的样本作本地 Qwen3-TTS 的参考音频：预置"苏打"（男）中位 f0 **140.4 Hz**、设计"女学者" **193.5 Hz**、内置 `zeyu_zh` 101.7 Hz —— **音色确实变了**，且都正常出声、时长合理 |

最后一行是这套方案的地基：**MiMo 生成的音频可以直接当 Qwen3-TTS 的克隆参考**，
所以"云端只造一次音色、逐页仍本地合成"这条路线成立。

**落地清单**

| 文件 | 内容 |
|---|---|
| `scripts/mimo_voice.py`（新增） | 预置/描述两种生成 + 缓存（`jobs/_voices/<key>.wav\|.txt\|.json`）+ `resolve()`（**任何失败都回落内置音色**）+ CLI（`--list` / `--kind`） |
| `web/app.py` | `/api/voices/generate`（生成或取缓存）、`/api/voices/{key}/sample`（试听）、`/api/voices/upload`（ffmpeg 统一解码 + 3~30 秒校验）、`/api/options.voice`、建任务时解析音色（回落会回给界面）、`_build_argv` 透传、`[voice]` 写进 run.log |
| `pipeline.py` / `pipeline_light.py` | **ref_text 跟着 ref_audio 走** —— 修掉"自定义音频 + 档位文本"张冠李戴的隐患（这种错不报错、只听得出音色不像） |
| `web/frontend/src/App.tsx` | 音色区四选一 + 试听 + 重掷 + 上传 + 参考文本；任务列表显示该任务用了哪个音色 |

**执行期发现的一个特性**：**已生成的音色不需要 key**（缓存命中直接可用）。
也就是说即使"限时免费"哪天结束，使用者攒下来的音色资产仍然能用 ——
这条已经被测试钉住（`没配 key 且没有缓存 -> 回落` 与 `已生成的音色没有 key 也能用` 是两个相反的断言）。

**测试**：冒烟测试新增第 10 组（35 项，含一条端到端：建任务 → config → 真实命令行），
全量 **161 项通过**。所有网络路径都用假 client / 缺 key 覆盖，**不消耗真实配额**。
