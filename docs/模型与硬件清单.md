# Paper2Video / PaperTalker 模型与硬件清单

> 依据：`docs/Paper2Video.pdf`（arXiv 2510.05096v2）正文与附录，以及 `Paper2Video-main/src/` 的实际代码。
> 本机环境：Windows 11 (26200) / AMD Ryzen 7 9700X 8C16T / 64 GB DDR5-5600 / RTX 5070 Ti 16 GB（驱动 591.86，CUDA 13.1，sm_120）。
> 硬件数字为**依据参数量与官方说明的估算区间**，非实测；显存占用随 batch、分辨率、量化方式变化。

## 二、本地部署模型逐个说明

### 1. F5-TTS —— 语音合成
- **代码位置**：`src/speech_gen.py`（`from f5_tts.api import F5TTS`）
- **功能**：输入「幻灯片逐句字幕 + 10 秒参考音频 + 参考文本」，输出该讲者音色的逐页 wav。
- **规模**：约 0.34 B 参数。
- **显存估算**：**≈ 2~4 GB**（含声码器与参考音频编码）。
- **依赖**：`f5_tts==1.1.6`。参考文本缺省时会先调 WhisperX 转写参考音频。
- **本机结论**：**可行**，单卡无压力。

### 2. UI-TARS-1.5-7B —— 光标空间定位
- **代码位置**：`src/cursor_gen.py:44`，`pipeline("image-text-to-text", model="ByteDance-Seed/UI-TARS-1.5-7B")`
- **功能**：把「本句要指向幻灯片上的哪一处」翻译成像素坐标，输出 `click(point='<point>x y</point>')` 再由正则解析出 (x, y)。
- **规模**：7 B 参数。
- **显存估算**：fp16/bf16 权重本身 **≈ 14~15 GB**，叠加视觉编码器与 KV cache 实际需 **≥ 16~18 GB**；4-bit 量化后 **≈ 5~7 GB**。
- **关键约束**：代码用 `multiprocessing.Pool(processes=num_gpus)`，**每个进程各加载一份完整模型**。单卡跑就只会起 1 个进程，但换卡并行时是「每卡一份权重」的线性叠加。
- **本机结论**：**开箱不可行**。16 GB 卡装不下 bf16 的 7B VLM，必须走 AWQ/GPTQ 4-bit 量化或改调云端 VLM 接口。

### 3. WhisperX（large-v2 / large-v3）—— 时间对齐
- **代码位置**：`src/cursor_gen.py:159`（`large-v3`）、`src/speech_gen.py:13`（`large-v2`）、`src/evaluation/MetaSim_content.py:71`（`large-v3`）
- **功能**：转写音频并做强制对齐，拿到**词级时间戳**，从而推出每句光标片的 start/end。
- **显存估算**：fp16 下 **≈ 2~3 GB**（large-v3 + VAD + 对齐模型）。
- **本机结论**：**可行**。
- **注意**：`cursor_gen.py` 里模型加载写在循环**外面**（只加载一次），但 `speech_gen.py:53` 的 `transcribe_with_whisperx` 在逐页循环**内部**被调用，传了 `ref_text` 才能跳过——否则每页都会重新载入一次大模型。这是实打实的性能坑。

### 4. Hallo2 —— 数字人渲染
- **代码位置**：`src/talking_gen.py`（`sys.path.insert(0, "hallo2")`，复用官方 `inference_long.py` + `long.yaml`）
- **功能**：给定人像 + 该页语音，生成口型同步的头部特写视频；再与原幻灯片叠合成完整演讲视频。
- **模型组成**：Stable Diffusion 1.5 UNet + AnimateDiff 运动模块 + wav2vec2 + sd-vae-ft-mse + RealESRGAN + CodeFormer + insightface/mediapipe 人脸分析 + MDX-Net 人声分离。**权重合计约 15 GB**。
- **显存估算**：官方口径不一——项目方技术反馈 **约 12 GB 起**，第三方评测写 **16 GB+**。实操建议按 **12~16 GB 独占**预留。
- **硬性障碍（对你尤其重要）**：
  - Hallo2 官方锁定 **torch 2.2.2 + CUDA 11.8**，只测过 **Ubuntu 20.04/22.04**。
  - RTX 5070 Ti 是 Blackwell 架构 **sm_120**，cu118 的 torch 2.2.2 **不含 sm_120 的编译目标**，装上会直接报算力不支持。
  - 必须把 Hallo2 环境里的 torch 升到 **2.7+ / cu128** 才有 sm_120 支持，但随之要处理 `basicsr`、`xformers`、`insightface` 等一串原生依赖的兼容问题。
  - Windows 原生跑这套（insightface/onnxruntime + mediapipe + basicsr + ffmpeg）成功率低，**建议走 WSL2 或 Linux**。
- **本机结论**：**显存勉强够（需独占），但架构与系统是真正的拦路虎**。

### 5. SpeechBrain ECAPA-VoxCeleb —— 音色相似度
- **代码位置**：`src/evaluation/MetaSim_audio.py:26`（`speechbrain/spkrec-ecapa-voxceleb`）
- **功能**：把生成语音与真人语音各编码成说话人嵌入，算余弦相似度，即论文 Table 2 的 Speech Similarity。
- **显存估算**：**< 1 GB**（ECAPA-TDNN 仅约 80 MB 参数）。
- **本机结论**：**可行**。

## 三、只走 API 的部分

| 脚本 | 调用的模型 | 环境变量 / 位置 |
|---|---|---|
| `src/pipeline*.py`（幻灯片、字幕光标） | GPT-4.1（默认）/ Gemini-2.5-Pro / Qwen 等 | `OPENAI_API_KEY`、`GEMINI_API_KEY` |
| `src/evaluation/MetaSim_content.py` | Gemini（VLM 打相似度分） | `os.environ["GEMINI_API_KEY"]`（脚本内硬编码为空） |
| `src/evaluation/PresentArena.py` | `models/gemini-2.5-pro` | `genai.configure(api_key="")`（脚本内硬编码为空） |
| `src/evaluation/IPMemory/ip_qa.py` | `models/gemini-2.5-pro-flash` | 同上 |
| `src/evaluation/PresentQuiz/create_paper_questions.py` | 默认 `4o`，可选 `o3` / `gemini` | `os.environ["OPENAI_API_KEY"]` |
| `src/evaluation/PresentQuiz/PresentQuiz.py` | Gemini | `os.environ["GEMINI_API_KEY"]` |

**两个要留心的点**：
1. **API Key 是硬编码的空字符串**，写在脚本里，不是统一的 `.env`。逐个文件手工填是必需的步骤。
2. `ip_qa.py` 里的模型名 `"models/gemini-2.5-pro-flash"` **不是 Google 的合法模型 ID**（应为 `gemini-2.5-pro` 或 `gemini-2.5-flash` 二选一），照抄会直接报模型不存在。

## 四、论文自己报的硬件

- 正文 5.1 节：*"We perform inference using eight NVIDIA RTX A6000 GPUs."* → **8 × 48 GB = 384 GB 显存**。
- README：*"The minimum recommended GPU for running this pipeline is NVIDIA A6000 with 48G."*
- 之所以要这么多，是因为**逐页并行**：幻灯片各有独立的 TTS / 光标 / 数字人三条流水，`multiprocessing.Pool` 按 `gpu_list` 铺开。单卡不是不能跑，是**线性变慢**。
- 论文同时报告了耗时：完整版平均时长 234.36 秒的视频生成，Talking-head 是绝对瓶颈（"generating only a few minutes of talking-head video typically takes several hours"）。

## 五、本机（RTX 5070 Ti 16 GB）可行性小结

| 环节 | 显存需求 | 本机判定 | 说明 |
|---|---|---|---|
| F5-TTS 语音 | ≈ 3 GB | 可跑 | — |
| WhisperX 对齐 | ≈ 3 GB | 可跑 | — |
| SpeechBrain 评测 | < 1 GB | 可跑 | — |
| UI-TARS-1.5-7B 光标 | ≈ 15 GB（bf16） | **不可行** | 需 4-bit 量化，或改用云端 VLM 出坐标 |
| Hallo2 数字人 | ≈ 12~16 GB | **勉强** | 需独占显存；且 sm_120 + Windows 双重障碍 |
| 幻灯片 / 字幕 / 评测 | 0（纯 API） | 可跑 | 需自备 OpenAI + Gemini Key |

**两点容易被忽略的现实约束**：
- 采集时 `nvidia-smi` 显示显存**已被占用 6.8 GB**（可用约 9.5 GB）。真正跑大模型前要先清出显存。
- E: 盘剩 874 GB、F: 盘剩 1897 GB。Hallo2 权重约 15 GB、F5-TTS + WhisperX 约 5 GB、再算上 Qwen 类本地模型，**空间充足**；唯一紧张的是 C 盘（剩 24 GB）——注意 HuggingFace 默认缓存会写 C 盘，需改 `HF_HOME`。

### 建议的推进路线

1. **先走 `pipeline_light.py`**（无数字人）：只需 F5-TTS + WhisperX + UI-TARS(量化) ，避开 Hallo2 的全部坑。
2. **光标模块可先降级**：把 UI-TARS 换成云端 VLM 出坐标，或用 4-bit 量化版，先跑通链路再谈质量。
3. **数字人单独最后做**：放到 WSL2/Linux 环境，torch 升 cu128，参照 Hallo2 的 Docker 镜像起步。
