## 三、根因：入选门槛要求"溢出页 **且** 该页含图片"

```python
# slide_code_gen_select_improvement.py:190-197
for warning in warning_info:                 # 只留 'Overfull' 的行
    num = int(re.search(r'(?<=\.tex:)\d+', warning).group())
    for idx, f in enumerate(frames):
        if f["start_line"] <= num <= f["end_line"]:
            if "\\includegraphics" in f["text"]:     # ← 门槛
                need_improve_list.append(idx)
```

实测代入这份论文的真实数据：

```
日志 warning 行 115 条 → 取前一半 57 条 → 其中 Overfull 48 条
涉及 slides.tex 行号（去重）: 15, 21, 32, 43, 54, 64, 75, 86, 96, 106, 116, 125
slides.tex：\includegraphics 0 次 | \begin{frame} 11 次
每一处溢出都落在某个 frame 里，但**11 个 frame 里含图片的 = 0 个**
=> need_improve_list = []
```

**所以不是坏了，是没活可干。** 树搜索只会缩放 `\includegraphics` 的宽度——
它的设计目标就是"图片太宽 → 试几个宽度让图不出框"。纯文字的溢出（
`Overfull \hbox ... in paragraph`）它**无能为力**。

## 四、为什么我们的幻灯片没有图（两层原因，都要知道）

**第一层（结构性，影响所有论文）**：喂给幻灯片生成模型的 LaTeX 工程里**没有图片文件**。
`latex_code_gen_upgrade()` 会把工程目录下的**文件路径清单**写进提示词：

```
The file pathes in the project are: ['main.tex', 'main.pdf']
```

而我们的前端是 `paper_ingest → paper_struct`：PDF/Word **只提取正文文本**，
产出的 `main.tex` 是纯文本工程，**不带任何 figure**。上游原本的用法是
「`--paper_latex_root /path/to/latex_proj`」——**用户自己提供带图的 LaTeX 工程**。
我们这条自研的输入端，天然把图丢了。

中文提示词也明确授权模型不画图：**「若没有可用图片，**不要写任何 `\includegraphics`**」**
⇒ 模型的行为是**正确**的，它照做了。

**第二层（这篇论文本身）**：`FS202506228孟欣影视表演.pdf` 里**内嵌图片总数 = 0**
（5 页，每页 0 张）。所以就算插上图片提取，这篇也没有图可用——它是纯文字的理论文章。

历史上三份幻灯片全部如此：

| 任务 | `\includegraphics` | frame 数 |
|---|---|---|
| `job_0919_021443_f700` | 0 | 14 |
| `job_0919_110711_f556` | 0 | 16 |
| `job_0919_112026_8f57` | 0 | 11 |

## 五、什么条件下这个开关才会真的做事

三件事必须同时成立：

1. **论文里有图**，且图能被取到（PDF 内嵌图 / `.zip` 或 `.tex` 工程自带的图片文件）；
2. 图被**放进 `paper_latex_root`**，于是文件名出现在给模型的路径清单里，幻灯片才会 `\includegraphics` 它；
3. 那张图**宽度溢出**（`Overfull \hbox` 落在这个 frame 里）。

只要第 1 或第 2 条不成立（现在**必然**不成立），开关就是**空转**：
不花钱、不报错、也不产出任何改进。

## 六、要让论文的核心机制真正跑起来，需要补什么

| 改动 | 说明 |
|---|---|
| **提取论文图片** | `paper_ingest` 阶段把 PDF 内嵌图（`page.get_images()`）或 `.docx/.zip` 里的图片导到 `<job>/latex_proj/figures/`，在 `main.tex` 里以 `figure` 环境引用 |
| 图片筛选 | 只留够大的（如短边 ≥ 200px）、去重（同图多次出现），并给出文件名的**语义名**（图 3 流程）便于模型用对 |
| 提示词 | 中文模板已支持"有图则用"，无需改；但要保证路径清单里**真能看到**这些文件 |
| 验证 | 重新跑一篇**有图**的论文，检查 `slides.tex` 的 `\includegraphics` 次数 > 0、且 `proposal_imgs/` 非空 |

⚠️ **成本预告**：真的触发后，**每张溢出页**要多 4 次 LaTeX 编译 + 4 次渲染 +
**1 次带图 VLM 调用**。这才是这个开关的真实价钱（本次因为空转，代价约等于 0）。

## 七、附带发现（都还没有修，按影响排序）

1. **`warning_info[:len(warning_info)//2]` 是个脆弱的启发式**（第 182 行）。
   它假定引擎会把每条 warning 打印两遍（tectonic 第一遍 + rerun 时一遍）。
   本次实测 115 条 warning 取前 57 条恰好覆盖（48 条 Overfull），但**这个一半是多出来的**——
   一旦引擎的输出格式变化（少打一遍/多打一遍），会**静默丢掉一半溢出页**或**重复计入**。
2. **`slides_refined.tex` 不是原文件的忠实副本**：重建时会丢掉模型写的注释
   （实测 23 行差异里 11 行是 `% ===== 封面页 =====` 这类注释被删）。
   本次两版 PDF 字节数完全相同（225.8701171875 KiB）⇒ 产物无损，但源码可读性变差。
3. `\setbeamerfont{caption}{size=\scriptsize}` 会被无条件加进 head（第 187 行），
   即使没有任何 caption —— 无害，但说明"refined 版"这个名字有点名不副实。
