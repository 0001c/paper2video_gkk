可以结合。优先提炼真实课堂的教学方法和完整示范片段，再作为生成时的参考；先验证效果，再考虑训练模型。普通视频总结主要保留知识结论，容易删掉设问、铺垫、分步推导、错误分析和过渡，不能直接替代教学范例。

## 建议的最小流程

1. 人工选定同一教材章节或高度相关知识点的少量优质讲课视频，从映知导出 SRT 或通过现有鉴权接口读取 JSON。首轮以文件交接降低两个服务的耦合。
2. 按完整教学意图切段，保留必要前后文：引入一个概念、完整解一道题、解释一种误区。不要只按固定字数抽碎片。去除广告、闲聊与无意义重复，纠正可核验的 ASR 术语错误，保留原文。
3. 提炼教学范例卡。字段建议为：学科、知识点、受众、先修要求、教学目的、引入问题、解释步骤、例题或类比、易错点、检查理解的问题及解释、总结与过渡、原字幕摘录、来源引用、审核状态。
4. 引用保留 BVID、分 P/cid、原网址、segmentIds、startMs/endMs、字幕 checksum、来源类型和提炼版本；毫秒时间从原片段计算，不由模型猜测。外部字幕始终作为参考数据处理。
5. 按当前教材知识点、受众和先修要求，先用人工选择或简单标签匹配少量范例。分开保存可跨学科使用的讲解方法与需要同知识点校验的例题/解释。
6. 在课件生成之前，结合教材与范例产出可审核的全课教学提纲：每段要解决的问题、讲解顺序、例题步骤、误区、设问及解答位置、时间预算。随后共同约束课件与逐页讲稿。
7. 逐页生成时提供当前页教学任务、教材证据、相关范例和前后衔接计划。范例的步骤结构可借鉴；专业事实、数值、例题结论须对照教材或独立核验，补充例子明确标注，不能冒充教材原题。
8. 保留现有讲稿格式归一化、例题/预算门禁、知识问答、人工审核及配音流程。微课中的提问需要随后解释，不能假装收到了学生回答。

字幕无法完整表达板书、手势、动画和停顿；出现“看这里”“这个式子”等依赖画面的片段须补看对应画面，无法核验时标记缺失或弃用，不能让模型补造。本轮范围是讲稿，不包含音色或声线模仿。

## 第一轮对照试验

建议选一个当前讲稿明显不足的章节，人工挑选约 3–5 个相关教学片段，覆盖 2–3 个关键知识点；数量只是试验起点，不代表足够训练模型。

- A：当前生成流程。
- B：加强教学规划/提示词，但不提供视频范例。
- C：同样的规划加经审核的教学范例。

固定源材料、受众、知识范围、页数、时长预算、生成模型及主要参数；保存模型响应、实际用量、范例版本与生成配置。先比较讲稿，初轮不必生成全部成片。使用相同配音配置试听代表性片段；条件允许时重复少量生成，观察随机波动。

评价分别记录：事实和例题正确性、先修知识匹配、概念解释和推导是否完整、误区是否具体、设问是否闭环、过渡与口语自然度、时长。评审时隐藏版本标签，优先由教师或目标学习者比较。知识评价继续使用从教材冻结的同一组题目，避免不同题库分数直接比较；评审喜好与模型问答不能替代真实学习效果测量。

只有 C 在正确性和预算不退步的前提下，稳定优于 A/B，才扩展范例库并建设检索。若只 B 改善明显，先投入教学规划。后续微调需要经审核的“教材片段＋受众＋教学目标 → 优质讲稿”配对样本，不能把原始字幕直接当作训练答案；训练/验证应按课程或来源视频分组，避免相邻片段泄漏。

## 实施边界与后续接口

建议先保持两项目独立：映知负责视频和字幕获取，本项目负责教材教学设计、讲稿与成片。第一阶段新增教学范例导入/审核、教案中的范例选择、生成上下文注入；大规模向量库、自动全站采集和模型训练留待试验结果决定。

后续实现需将教材、字幕 checksum、范例选择与内容、审核后的教学提纲、提炼提示词版本纳入计划 token、逐页缓存和外层课件/讲稿产物缓存的身份；保留当前任务原稿和来源快照，避免参考变化后误用旧缓存。仅更改逐页 prompt 不能代替检查外层缓存。

样本采用可合法使用且来源明确的内容；公开发布、共享语料或开展训练前确认对应素材的使用权限。优先学习通用教学组织方法，避免大段复制特定老师的表达。

本轮仅完成代码与文档调研，没有修改运行时代码、重启服务、读取用户凭据或调用付费生成模型。

- [Distilling Step-by-Step!](https://aclanthology.org/2023.findings-acl.507/)：研究用教师模型生成的推理解释训练较小模型。严格的模型蒸馏涉及训练；本方案首阶段是教学范例提炼与生成上下文增强，两者应区分。
