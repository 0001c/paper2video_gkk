## 遇到的问题及以后注意

1. Windows 沙箱无法创建 asyncio 所需本机 socketpair，FastAPI TestClient 会卡在事件循环初始化。通过 faulthandler 定位，与应用路由无关。核对命令行只停止本轮挂起的测试父子进程，然后提权运行同一套替身测试即通过；不要为此改生产中间件。沙箱 CIM 读取也不可用，进程核对需提权。已核对并删除本轮两个残留的 `.course-smoke-*` 临时目录。
2. 扩展回归发现旧测试会破坏缓存最终文本。新缓存有有效候选历史，可据此恢复而不重新付费；调整测试明确验证这项行为。只有完整缓存和历史都不可用时才视为缺页。
3. 仅缩短讲稿会与初始文字预算冲突：示例设定 220 单位/分钟、实际读 80 秒，缩为 165 单位后原预算会判太短。新增同音色实测 165 单位/分钟的下一次修订校准。校准是全课平均；每页停顿和内容差异仍会影响实测，最终仍以 WAV 验收。
4. 校准依据当前音频 manifest 的身份；切换成尚未完成配音的新音色时，仍需要新一轮实际测量。不要把旧音色测量当作新音色的保证。混合音色、未知身份、越界语速不自动采用。
5. 数学检查是有限语法，不能覆盖全部公式或语义证明；报告 passed 仅指当前门禁通过。A1 深谷结论、普遍收敛保证等仍需人工审阅。正则提取失败不能记为已核验，不应让模型评审分覆盖确定性反例。
6. 教学按页顺序生成会降低并发；早期页口播摘要和教材长文窗口仍有丢细节边界。跨页问题兑现目前靠明确任务和提示词引导，没有自动语义证明。不要在未经等时长真实对照前把工程回归当成教师风格收益。
7. 成功候选即时落盘并限制修正；耗尽额度会停到审核。旧任务继续复用原讲稿；只有显式重写/新建任务才应用新的生成，不能为展示升级自动触发收费重做。
8. 生产运行中的 Python 后端需要加载新代码；前端已本地构建到 Git 忽略的 web/static，未重启现有服务、未部署。无新 API 写入通道，既有审核协议保留。
