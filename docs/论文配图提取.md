# 论文配图提取（`scripts/paper_figures.py`）

> 实施时间：2026-09-19 | 状态：**已实施**（全量测试 310 项通过）
> 触发：使用者问「树搜索为什么这么快」→ 查出**幻灯片里从来没有图** → 查出提图这一步根本不存在。

## 一、为什么必须有它

上游 Paper2Video 的入口是「**带图的** LaTeX 工程」（`--paper_latex_root /path/to/latex_proj`），
而我们这条自研链路从 PDF / Word 出发，`paper_ingest` **只提取正文文本** ——
于是 `latex_proj/` 里永远只有 `main.tex`：

```
提示词里给模型的文件清单 = ['main.tex']        ← 没有任何图片文件
```

中文提示词又明确写着「**若没有可用图片，不要写任何 `\includegraphics`**」，
所以模型的行为是**正确**的：幻灯片里 0 张图。

**后果远不止"幻灯片不好看"**：树搜索（`--if_tree_search`）只会缩放
`\includegraphics` 的宽度，入选门槛是"Overfull 溢出的页 **且** 该 frame 含图片"
⇒ 它在这条流水线里**恒为空转**（详见 `docs/树搜索实测.md`）。

实测证据（同一篇论文，PDF 里有 2 张内嵌图）：

| 任务 | 幻灯片张数 | `\includegraphics` 次数 | `proposal_imgs/` |
|---|---|---|---|
| `job_0919_112342_5fb6` | 15 | **0** | 空 |
| `job_0919_021443_f700` | 14 | **0** | 空 |
| `job_0919_112026_8f57`（纯文字论文） | 11 | 0 | 空 |

## 二、它做什么

从原始上传件提图 → 落到工程的 `figures/` → 生成清单 → 清单进幻灯片提示词。

```
<job>/latex_proj/figures/
    fig01_p06.jpg      ← 第 6 页的第 1 张（文件名纯 ASCII）
    fig02_p09.jpg
    index.json         ← 版本 / 源指纹 / 每张的页号·尺寸·图题
    README.txt         ← 给人看的
```

流程（`pipeline.py` stage 1 内，**复制之后**）：

```
复制工程 → paper_figures.extract(--paper_source, 复制后的工程)
        → figure_prompt_block() 拼清单 → 附进 slides 提示词的 extra_prompt
```

附给模型的清单长这样（实测输出）：

```
本项目已经提供了论文里的插图（放在 figures/ 下），请**优先**在内容匹配的幻灯片上
用 \includegraphics 引用它们：宽度用相对值（如 width=0.8\textwidth），给它加 caption，
不要引用上面列表之外的图片。

  - figures/fig01_p06.jpg  —— 图1 AI训练语境用途表达的无监督结构识别结果
  - figures/fig02_p09.jpg  —— 图2 不同阈值条件下科研用途语义覆盖度（SCI）的变化趋势
```

## 三、六个必须记住的设计决定

### 1. 提图只在**一个地方**做，且在 `copy_folder` 之后

`pipeline.py` 会把 `paper_latex_root` 整体复制到 `<result_dir>/latex_proj`，
之后**模型读的是副本**。而 `copy_folder` 只在目标不存在时执行 ——
所以"重跑/续跑旧任务"时副本是旧的。

第一版我在 `web/app.py` 里往**源工程**写图。那样会出现：副本里没有图 → 提示词读不到，
而日志还显示"已附清单"（因为它读的是另一份路径）。**这正是本仓库反复踩的
"两个读取者各读各的"坑**（`_result_dir` 那次也是）。现在只有一个写入点，
物理上不可能不一致；测试里有一条顺序守卫（`copy < extract`）钉住它。

### 2. 图片格式一律转 PNG/JPEG —— 这条不是洁癖

期刊 PDF 的内嵌图常见 **`.jpx`（JPEG2000）**，而 XeTeX/tectonic 的
`\includegraphics` **不支持**它。实测那篇论文的两张图**都是 jpx**：
直接落原格式会得到"编译时才报错"的坑。

而有损源转 JPEG 而非 PNG：161 KB 的 jpx → PNG 会膨胀到 **1134 KB**，
JPEG(q92) 回到 **377 KB**，视觉无差。

**判据是文件头而不是扩展名**（测试里按 magic bytes 断言）——
否则"jpx 原样写出但名字叫 .jpg"会溜过去。

### 3. 文件名只用 ASCII

`fig01_p06.jpg`。本仓库已经因为中文路径/中文编码踩过多次（LaTeX 宏包、
stdout 编码、`cv2.imread`），示意图文件名不值得再赌一次。
图的**语义**（图题、页号）写在 `index.json` 里，由清单带给模型。

### 4. 没有图时**什么都不留**

纯文字论文如果留下 `figures/index.json` + `README.txt`，那么提示词会收到
这两个路径（提示词带的是"工程里所有文件的清单"）⇒ 与接通提图之前**不再逐字节一致**
⇒ deck 指纹变化 ⇒ **使用者要为"其实什么都没变"再付一次幻灯片生成的钱**。

所以：没找到图就删掉自己产生的文件与目录，`figure_prompt_block()` 返回空串。

### 5. 幂等判据必须含**源指纹**，不只是版本号

`index.json` 记 `version` + `source_sha1`，两者都一致才跳过。
光比版本号的话，"工程目录被复用、但换了源文件"时会错误跳过，
症状是"换了一篇论文，幻灯片里还是上一篇的图"——**不报错**。

（同类纪律：`_upload_work` 的命中判据、`artifact_cache` 的 `REQUIRED_FIELDS`。
凡"算出来的东西既用于查询又用于写入"，都要问一句"判据里含输入本身吗"。）

### 6. "工程自带图"的判定 = `\includegraphics` 真正引用的文件

**不是**"目录里有没有图片文件"。第一版按扩展名扫，结果把 `main.pdf`
（LaTeX 编译产物，工程里必然有）当成了"自带图"⇒ **纯文字论文也被判成有图**
⇒ 提图被跳过、指纹记成 `own:` ⇒ 与"真的没有图"混为一谈，且不报错。
现在改成扫所有 `.tex` 的 `\includegraphics{...}` 并解析出真实存在的文件。

## 四、筛选规则（实测标定，不是猜的）

| 规则 | 值 | 依据 |
|---|---|---|
| 显示区域占页 | ≥ 3% | 实测两张真图占页 35.2% / 6.8%；装饰元素远小于此 |
| 源图短边 | ≥ 150 px | 过滤 logo / 图标 / 公式碎片 |
| 去重 | 按图内容 sha1 | 同一张图在多页重复出现时只留第一处 |
| 上限 | 12 张 | 避免"图太多把文字挤没" |
| 最长边 | ≤ 2400 px | 避免超大图拖慢编译 |
| 矢量簇 | 占页 ≥12% 且宽 ≥30% 页宽 | ⚠️ **未标定**：手头两篇 PDF 各聚类出 0 簇，规则保守、标记 `kind=vector` 便于核对 |

## 五、与产物缓存的关系

`figures` 进了 `DECK_FIELDS`（`artifact_cache.py`）。理由是实的：
**幻灯片里能不能出现 `\includegraphics` 完全取决于"工程里有哪些图"**，
漏掉它就会出现"补充图片之后仍命中没有图的那一版缓存"，表现为
"幻灯片里怎么还是没有图"，且不报错。

它**不进** `STRUCT_FIELDS` —— 图不影响 `main.tex`，进了就白花一次结构化的钱。

字段值的两种形态：

| 形态 | 含义 |
|---|---|
| `v<版本>` | 我们自己从源文件提取（或没有图）。图集是 `(源文件, 提取器版本)` 的确定函数，而源文件已由 `source_sha1` / `main_tex_sha1` 覆盖 ⇒ **只需版本号** |
| `own:v<版本>:n<数量>:<清单哈希>` | 工程**自带**、被 `\includegraphics` 引用的图（上游用法） |

⚠️ 这一支刻意**不读 `figures/index.json`**：读了就要求"提图必须先于指纹计算"，
于是写入点在 web 层、用图的人在流水线里 —— 又是两个位置。实测这种漂移真的会发生（见 §3.1）。

**提图逻辑升级（阈值、命名、筛选）必须把 `FIGURES_VERSION` +1**，
否则会命中"用旧逻辑提的图"生成的那批幻灯片。

## 六、缓存影响面（本次已处理）

新增指纹字段会让已有 deck 条目全部换键。处理方式是**按证据逐个判定**：

| 条目 | 论文 | 判定 | 动作 |
|---|---|---|---|
| `3c08e5d9e19e` | 孟欣影视表演（0 张图） | 输入与产出时完全一致 | **改名迁移** → `deac1030094f`，job.json 同步 |
| `ad10138cf5c3` | 科学数据（2 张图） | 图集 0 → 2，产物真的不同 | **留原地**（已被取代，`plan_gc` 列为可回收 4.6 MB） |
| `f81d459f7ee9` | 科学数据（2 张图） | 同上 | **留原地**（可回收 4.7 MB） |

**为什么不迁移"有图"的那些**：改名等于把"没有图的产物"冒充成"有图的产物"，
正是这个仓库最怕的静默错配。它们应当在下次同参运行时**重新生成**（一次 stage 1 的费用）。

## 七、验证方式

```bash
# 离线自检（不调 API）：合成 PDF / 合成 docx / 反面对照
python scripts/smoke_web_api.py            # 第 14 组，26 项断言

# 单跑提图并看清单
python scripts/paper_figures.py \
  --source jobs/_content/<sha>/input/<sha>.pdf \
  --project <某个 LaTeX 工程目录>

# 决定性判据：图能不能真的进幻灯片（tectonic 实测）
#   probe.tex 必须放在**工程根目录**（与 figures/ 同级），否则相对路径找不到图
tectonic probe.tex && python -c "import pymupdf;d=pymupdf.open('probe.pdf');print(d[0].get_images())"
```

## 八、还没做的

1. **矢量图阈值未标定**（`cluster_drawings` 在手头样本里都是 0 簇）。遇到真正的
   矢量图论文（matplotlib 直接导 PDF 的那种）要重新标定，并核对是否会捞出表格框线。
2. **图片语义只有图题**，没有"哪张图对应论文哪一节"。模型只能靠图题猜。
   接下一步可考虑把图片所在页的正文段落也带上。
3. **图片没有进 `_content` 内容库**：每次新任务都会重新提取（本地、亚秒级，
   且结果确定了 deck 指纹），所以没做缓存。真要做也要按 `(sha1, FIGURES_VERSION)` 命名。
