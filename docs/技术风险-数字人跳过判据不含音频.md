# 技术风险：数字人阶段的跳过判据不含音频

> 发现时间：2026-09-19 01:30
> 状态：**已修**（2026-09-19 02:0x，按下面的方案 A 落地；见文末「已实施」）
> 触发场景：顺着「要不要加'复用某任务的产物'入口」这个问题查代码时发现

## 一句话

数字人的「已存在则跳过」只看**页号 + 参考图文件名**，不看音频。
于是**音频变了、页数与人像文件名没变**时，该页会被跳过，
**旧配音连同旧数字人视频一起进成片，本次新生成的 TTS 音频被静默丢弃** ——
全程不报错，只有看/听成片才能发现。

## 证据（三处，都在主链路上）

**① 跳过键只有两个字段** —— `Paper2Video-main/src/talking_gen.py`

```python
def _target_paths(save_dir, idx, ref_img_path):
    ref_stem = path.splitext(path.basename(ref_img_path))[0]
    target_dir = os.path.join(save_dir, str(idx), ref_stem)
    return target_dir, os.path.join(target_dir, "merge_video.mp4")
```

判定点在两处，判据相同：单页路径 `:283`、批量路径 `:715`
（`if path.exists(target_video): ... 第 N 页已存在，跳过`）。

**② 合片不吃音频目录** —— `Paper2Video-main/src/merge_talking.py:45`

```python
def merge_slides_and_talking(slide_dir, talking_dir, output_dir, video_path,
                             num_video, ref_img, width, height, offset=10):
```

签名里**没有音频参数**；每页的音轨取自数字人视频自带那条
（进函数前还用 `_has_audio_stream(talking_path)` 校验过它必须有音轨）。
调用点：`pipeline.py:364`。

**③ 页展示时长跟数字人视频走** —— 同函数内 `duration = probe_duration(talking_path)`
用来循环幻灯片。所以音频换了，时长与字幕节奏也跟着错。

## 触发条件

| # | 场景 | 为什么会踩 |
|---|---|---|
| 1 | 续跑时显式 `reuse_script: False` | 讲稿重生成 ⇒ 音频重生成，但页数/人像名不变 ⇒ 跳过 |
| 2 | 讲稿文件丢失后被动重生成 | `pipeline.py:281` 是 `if args.reuse_script and path.isfile(...)`；文件不在就不成立 ⇒ 照样重生成，**哪怕请求里写了 `reuse_script=True`** |
| 3 | 将来若加「挂靠某个历史任务的产物」入口 | 同机制被放大：输入完全不同也照样跳过 |

场景 2 不是假想 —— 2026-09-19 那次误删（见 `事故记录-测试清理误删运行中任务.md`）
就把 `result/subtitle_w_cursor.txt` 一起删了，于是**任何**续跑都会走这条。

## 修法（按推荐度）

**A. 把音频指纹纳入跳过判据（治本，改动小）**
每个页目录落一份 `.inputs.json`，记录参考图与音频的 `size` + `sha1`；
跳过前比对，不一致就重生成。改 `_target_paths` 的调用点 2 处即可。
顺便能覆盖"换了人像但文件名相同"这种同源问题。

**B. 把「允许跳过」与「本次不会重生成音频」绑定（最小改动）**
stage 2 未复用讲稿时禁止跳过。缺点是耦合了两个概念，且对场景 3 无效。

**C. 产物目录按输入指纹寻址（长期）**
fingerprint = (论文正文, 人像, 讲稿, 音色) 四者的哈希 → 目录按指纹命名。
不用人挑、不会覆盖他人产物、天然跨用户共享，也顺手解决多人部署时的共享问题。

## 与「复用某任务产物」的关系

这个缺陷是**否决**那个功能的真正理由（不是权限）：
"挂靠历史任务"会把"输入不匹配"放大成静默的错误成片，
而 rerun 覆盖的是自己那份、语义明确、可预期。

若将来真要做跨任务复用，应当走 **C（内容寻址）而非任务寻址**。

## 已实施（2026-09-19，方案 A）

改的是 `Paper2Video-main/src/talking_gen.py`：

| 新增 | 作用 |
|---|---|
| `_inputs_fingerprint(ref, audio)` | 算这一页输入的指纹（两文件各 `size` + `sha1`） |
| `_inputs_unchanged(target_dir, ref, audio)` | 比对产物目录里的 `.inputs.json`，返回 `(能否复用, 原因)` |
| `_write_inputs_stamp(target_dir, ref, audio)` | 产物落盘后写下指纹（失败只提示，不影响出片） |

判定点两处都改了：单页路径 `_infer_task`、批量路径 `talking_gen_per_slide` 的过滤循环；
指纹写入点也是两处（各自 `merge_video.mp4` 落盘之后）。

**保守策略**：任何不确定都判为「不能复用」——
没有 `.inputs.json` 的旧产物、指纹读不动、当前输入读不动，一律重生成。
代价是重做一页（几十秒），收益是不会静默产出一版错配音的成片。
`_INPUTS_STAMP_VERSION` 参与比对，将来换判据口径时老指纹会自动失效。

**为什么用「原始输入路径」而不是暂存副本**：暂存路径是按页号复用的
（`TMP_DIR/talking/<backend>/<idx>`），跨任务会互相覆盖 —— 拿它算指纹，
第二次跑同一页时"输入看起来没变"，判据就失效了。批量路径为此专门记了
`inputs_of[idx] = (ref_img_path, audio_path)`。

**实测**（`scripts/smoke_web_api.py` 第 11 组，36 项断言）：
旧产物 → 不跳过；同一输入 → 跳过；**音频变了 → 拒绝复用**；
参考图变了 → 拒绝复用；指纹文件损坏 → 拒绝复用。
其中一条是**对照组**：同场景下旧判据（只看文件在不在）确实会跳过 ——
证明这不是假想问题。另有三条静态断言守着"两处跳过点都过指纹"，
防止将来被改回 `if path.exists(...)`。
