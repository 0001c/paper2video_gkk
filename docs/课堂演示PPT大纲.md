# Paper2Video 课堂演示 PPT 大纲

> 用途：课堂向同学与导师演示。本大纲可直接喂给 PPT 生成工具，或作为演讲逐页脚本。  
> 时长建议：15 分钟（正文 14 页 + 封面 + 结尾）。  
> 叙事主线：**问题 → 论文思路 → 我们落地时遇到的真问题 → 我们怎么解决 → 成果与展望**。

---

## 封面

**标题**：论文自动转学术演讲视频  
**副标题**：基于 Paper2Video 的国产化落地与工程化改造  
**演讲者 / 单位 / 日期**  
**一句话钩子**：把一篇论文，变成一段有幻灯片、有字幕、有真人数字人讲解的视频。

---

## 第 1 页 · 问题：学术演讲视频为什么难做

**核心信息**：学术会议普遍要求作者提交 2~10 分钟演讲视频，手工制作耗时数小时。

- 三件必须同时协调的事：**幻灯片设计** + **逐页录音** + **剪辑对齐**
- 一段 2~10 分钟的视频，背后是几小时的机械劳动
- 一个自然的问题：**能不能用 AI 自动生成？**

**演示要点**：先让听众认同「这事确实费劲、确实值得自动化」。

---

## 第 2 页 · 论文给了什么答案：Paper2Video

**核心信息**：我们要复现和落地的，是 Show Lab（NUS）的 Paper2Video 论文。

- 两大贡献：
  1. **Paper2Video 基准**：101 篇论文 + 作者真人视频，4 项评测指标
  2. **PaperTalker 框架**：首个多智能体学术视频生成框架
- 四条流水线：幻灯片 → 字幕 → 光标 → 数字人
- 结论：生成质量超过真人视频 10%，速度提升 6 倍

**演示要点**：点出「我们不是从零想，而是站在一篇成熟论文的肩膀上」。

---

## 第 3 页 · 但论文的原始方案，在我们这台机器上跑不起来

**核心信息**：论文假设的是 8×A6000 48GB 的服务器，我们是单张 RTX 5070 Ti 16GB。

| 环节   | 论文原模型      | 在 16GB 单卡上的死结                          |
| ---- | ---------- | -------------------------------------- |
| 光标定位 | UI-TARS-7B | bf16 需 15GB+，开箱 OOM                    |
| 数字人  | Hallo2     | 锁死 CUDA 11.8，不含 Blackwell(sm_120) 编译目标 |
| 语音合成 | F5-TTS     | CC-BY-NC 非商用许可证                        |

**演示要点**：这是本次工作最大的现实约束，也是「为什么要做国产化替换」的动机。

---

## 第 4 页 · 我们的目标：国产化 + 单卡可跑 + 可交付

**核心信息**：三个明确目标，决定了所有技术决策。

1. **模型全部国产化**（优先可用 > 效果）
2. **单张 16GB 卡能跑通**（分阶段加载，显存峰值 24GB+ → 约 10GB）
3. **许可证干净，可商业交付**（Apache-2.0 / MIT，避开非商用雷）

**演示要点**：把目标说清楚，后面每一页都在回应这三点。

---

## 第 5 页 · 模型替换总览：5 个异构模型 → 2 个模型家族

**核心信息**：本地侧从「5 个模型、3 套环境、2 个许可证雷」收敛成「2 个模型家族」。

| 模块        | 原模型              | 替换为                           | 许可证             |
| --------- | ---------------- | ----------------------------- | --------------- |
| 语音合成      | F5-TTS           | **Qwen3-TTS-1.7B**            | Apache-2.0      |
| 光标定位      | UI-TARS-7B       | **GUI-Owl-4B**                | MIT             |
| 转写对齐      | WhisperX         | **Qwen3-ASR + ForcedAligner** | Apache-2.0      |
| 数字人       | Hallo2           | **LongCat-Video-Avatar**      | MIT             |
| 语言/视觉 API | GPT-4.1 / Gemini | **DeepSeek-V4.1-Flash**       | 原生图像输入 + 1M 上下文 |

**演示要点**：强调「同源收敛」——Qwen 语音/视觉 + Wan 视频系，依赖栈能合并。

---

## 第 6 页 · 数字人是最难啃的骨头：两次换型

**核心信息**：数字人环节经历了 Hallo2 → InfiniteTalk → LongCat → MuseTalk三次换型。

- **Hallo2**：锁 cu118，架构不支持 sm_120，直接出局
- **InfiniteTalk**：Windows 原生下 fp8 加载触发 CUDA 扩展 JIT 编译，nvcc 无 compute_120，放弃
- **LongCat-Video-Avatar-1.5**：无需现场编译，只需一个「把 triton 改惰性导入」的纯 Python 补丁，但是模型参数过大，导致OOM，放弃
- MuseTalk：参数小，仅修改口型，速度快，显存占用低，在低配置机器可运行

**演示要点**：这是最有工程含金量的部分，体现「不是换个名字，是真刀真枪的排障」。

---

## 第 7 页 · 换 DeepSeek 几乎零改造：两个关键事实

**核心信息**：API 侧收敛到 DeepSeek，代码改动极小。

1. `get_agent_config()` 有兜底分支 → 传 `--model_name_t deepseek-flash` 即可，不用改代码
2. 光标坐标本就用 0-1000 归一化，与 GUI-Owl 同源

**但踩过一个隐蔽的坑**：DeepSeek 是推理模型，`max_tokens` 给小了会返回空答案**且不报错**——  
必须读 `finish_reason` 判断，而不是看 HTTP 状态码。

**演示要点**：展示「既有前人埋的顺路，也有必须亲自踩的坑」。

---

## 第 8 页 · 从命令行到 Web 界面

**核心信息**：把流水线包成网页，让0代码用户也能用。

```
上传论文(PDF/Word) → 选语言 → 填 API key → 点开始 → 看进度 → 拿成片
```

- 架构：React + FastAPI，前端只做外壳，**不碰算法**
- 三个刻意的工程选择：子进程调用（显存靠进程退出释放）、不经 shell、单 worker 串行队列
- 进度：流水线写 `progress.jsonl`，界面做「每页一个状态点」的细粒度展示

**演示要点**：现场可放一张界面截图，直观展示「普通人也点得动」。

---

## 第 9 页 · 一个必须解决的输入问题：使用者拿的是 PDF/Word，不是 LaTeX

**核心信息**：论文入口要求 LaTeX 源码，但真实输入是 PDF/Word，补了转换层。

```
.pdf / .docx / .doc ──► 提取文本 ──► LLM 结构化 ──► main.tex
```

- 实测三条结论：不用 Office COM（会挂死）、PDF 必须「行合并」、**`.pdf` 信噪比最高优先用**
- 保真度实测：8283 字 → 结构化 20 秒 / 10482 token → 编译成功，保留率 93.7%

**演示要点**：体现「真实世界输入 vs 论文假设输入」的差距，以及我们的补齐。

---

## 第 10 页 · 音色一致性：云端造一次音色，本地逐页克隆

**核心信息**：用 MiMo 云端生成一段音色样本，逐页仍本地 Qwen3-TTS 克隆。

- **为什么不是逐页调云端**：免费期结束就崩，且音色可能页间漂移
- **为什么音色只定一次**：全片 14 页必然是同一个声音
- **关键设计**：参考文本必须由我们给定（否则只能靠 ASR 转写，而 ASR 会转错）
- **兜底**：任何失败都回落内置音色，不阻断任务；已生成的音色不需要 key，资产长期有效

**演示要点**：这是「本地化原则」和「可用性」之间平衡的典型案例。

---

## 第 11 页 · 成本：一篇论文不到 1 元

**核心信息**：真正的瓶颈是本地生成时间（数字人），不是 API 钱。

| 项             | 数值                           |
| ------------- | ---------------------------- |
| 全流程 API token | 约 5.6 万（讲稿占 76%）             |
| 单篇 API 费用     | 约 $0.1~0.4（闲时）               |
| 真正耗时          | stage 2+3 约 13~15 分钟（本地 GPU） |
| 省钱主力          | `--reuse_script` 复用讲稿，只重跑后两步 |

**演示要点**：让导师看到「成本可控」，让同学看到「慢在哪、为什么」。

---

## 第 12 页 · 迁移准备

**核心信息**：本机是开发环境，搬到 Linux 服务器。

- 权重/缓存路径去盘符、GPU 档位不写死（用 profile 抽象）
- 多人使用要补：任务隔离、排队可见、按人统计 token、只监听内网
- 推荐 Docker：中文字体必须进镜像，权重走挂载卷

**演示要点**：体现「我们不是只做出能跑的 demo，还考虑了交付和迁移」。

---

## 第 13 页 · 踩过的坑

**核心信息**：选 2~3 条最能体现工程严谨的教训。

1. **`--if_tree_search` 默认关闭**：它是幻灯片布局微调（每张溢出页生成 4 个缩放候选、由 VLM 选一个）。关它是**成本**考虑而非"会崩"——上游那条 `else` 分支曾引用被注释掉的 import 而 NameError，该分支已被我们合并
2. **MuseTalk 偶数尺寸补丁**：人脸裁框为奇数 → libx264 拒绝编码 → 产物 0 字节，但上游照样打印「保存成功」
3. 数字人生成效果较差，需要进一步优化，模型参数过小

**演示要点**：用真实事故展示「我们踩了坑、也留下了纪律」，比空谈严谨更有说服力。
