## 1. 结论摘要

这是一个把**论文输入转为带幻灯片、配音、光标和数字人讲解的视频**的工程化项目。它由两层组成：

```text
使用者的 PDF / Word / LaTeX + 人像 + 音色
                 │
                 ▼
web/ 与 scripts/（本项目的产品层、输入适配和运维层）
                 │  子进程执行；单 GPU 串行排队
                 ▼
Paper2Video-main/src/（纳入本仓库的上游流水线及本地补丁）
                 │
                 ▼
jobs/<任务>/result/（过程产物） → MP4 / 幻灯片 / 音频 / 字幕
```

`Paper2Video-main/` 不是只读的 Git submodule，也没有被忽略；其中的补丁随本仓库提交。唯一需要单独安装、单独打补丁的数字人仓库是工作区外的 MuseTalk。根目录的 `README.md` 只有一句简介，真正的项目入口文档是 [项目讲解.md](项目讲解.md)、[代码改造总览.md](代码改造总览.md) 与 [Web可视化方案.md](Web可视化方案.md)。

当前工作区在记录时已有三项未提交的用户改动：`.workbuddy/memory/2026-09-19.md`、`docs/代码改造总览.md` 和 `Paper2Video项目汇报/Paper2Video项目汇报.pptx`。本记录不修改或覆盖它们。

## 3. 端到端执行链

### 3.1 Web 任务路径

`web/app.py` 的职责不是直接导入并运行模型，而是组装参数后通过 `asyncio.create_subprocess_exec` 启动上游 `pipeline.py`。这个边界很关键：子进程退出会释放模型显存，也便于取消、记录退出码和隔离崩溃。

```text
前端 App.tsx
  ├─ POST /api/ingest         上传论文并预览提取文本
  ├─ POST /api/portrait       上传人像
  ├─ POST /api/voices/*       选/造/上传参考音色
  └─ POST /api/jobs           建任务，进入单 worker 队列
          │
          ▼
web/app.py::_worker_loop / _run_job
  ├─ 结构化 PDF/Word → LaTeX 工程（必要时）
  ├─ 查/写结构化缓存、幻灯片与讲稿缓存
  ├─ 设置 UTF-8 与进度文件环境变量
  └─ 子进程运行 Paper2Video-main/src/pipeline.py
          │
          ▼
job.json + run.log + progress.jsonl + result/
          │
          ├─ GET /events：SSE 推送状态与进度
          ├─ GET /pages：页级素材索引
          └─ GET /files：支持 Range 的成品/素材下载与播放
```

服务默认只监听 `127.0.0.1`。单 worker 是显存约束下的设计选择，不应为追求吞吐直接改成多并发；每个并发模型进程都可能占满 16GB 显存。

### 3.2 上游主流水线的实际阶段

入口是 `Paper2Video-main/src/pipeline.py`；`pipeline_light.py` 是不含数字人的轻量分支。主入口的 `--stage` 使用 `"0"` 表示全流程，或选择 `"1"`、`"2"`、`"3"`：

| 阶段 | 主要代码 | 输入 | 主要输出 | 资源属性 |
| --- | --- | --- | --- | --- |
| 1. 幻灯片 | `slide_code_gen_select_improvement.py`、`pdf_render.py` | LaTeX 工程、LLM/VLM 配置、论文图片清单 | `slides.tex`、`slide_imgs/`、`slides_rendered.pdf` | API + 本地 TeX/PDF 渲染 |
| 2a. 讲稿 | `subtitle_cursor_prompt_gen.py` | 幻灯片图片 | `subtitle_w_cursor.txt` | VLM API；可用 `--reuse_script` 跳过 |
| 2b. 语音 | `speech_gen.py` | 讲稿、参考音频/文本 | `audio/<页码>.wav` | 本地 GPU；Qwen3-TTS 默认 |
| 2c. 光标 | `cursor_gen.py`、`cursor_render.py` | 讲稿、幻灯片、音频、同源 PDF | `cursor.json`、带光标画面 | 本地 GPU；GUI-Owl 定位 + 对齐 |
| 3. 数字人及合片 | `talking_gen.py`、`merge_talking.py`、`merge_video.py` | 人像、每页音频、幻灯片、光标 | 每页数字人视频、最终 MP4 | 本地 GPU + ffmpeg |

`sat.json` 记录阶段耗时，`token.json` 记录 API 用量。流水线启动时会先清理未运行阶段遗留的耗时键，避免旧运行的数字污染本次结果。

### 3.3 输出语言不是单一开关

`language_config.py` 把“幻灯片语言”和“讲稿/TTS/字幕语言”拆为两个轴。当前明确支持的常见预设是英文幻灯片 + 英文讲稿，以及英文幻灯片 + 中文讲稿；光标描述始终保持英文，因为其消费者是 GUI grounding 模型，而不是观众。

## 4. 输入、结构化与配图链

### 4.1 输入摄取：`scripts/paper_ingest.py`

这个模块只做本地、零成本的格式识别与正文提取，不做 LLM 章节重建。它先根据 magic bytes 而非扩展名分流，避免“改后缀的 docx 被当成 PDF”一类迟发故障。

| 格式 | 处理方式 | 重要局限 |
| --- | --- | --- |
| `.tex` / LaTeX `.zip` | 复制/解压为包含 `main.tex` 的工程 | 多文件工程入口必须可识别。 |
| `.docx` | `python-docx` 按段落提取，保留 Heading/Title | 使用者未用标题样式时仍需 LLM 推断结构。 |
| `.doc` | OLE `WordDocument` 流中的 UTF-16 可读段提取 | 有损，可能混入页眉页脚；建议转 docx。 |
| `.pdf` | PyMuPDF 提取后按句末/标题/空行合并硬换行 | 扫描版会标识为 `likely_scanned`，当前没有 OCR 主路径。 |

提取器版本由 `EXTRACTOR_VERSION` 控制，版本号参与缓存事实；改变提取规则时必须递增它，否则同一文件会误命中旧提取结果。

### 4.2 结构化与图片

PDF/Word 的正文会被结构化为上游所需的 `main.tex`。`scripts/paper_figures.py` 从 PDF/Word 提取插图，写入结构化后的 LaTeX 工程，并生成“文件名—图题—页码”清单。主流水线在**复制该工程到任务结果目录之后**才执行图片提取，保证模型看到的图片与真正被编译的工程属于同一份副本。

这一步是树搜索能有实际布局选择空间的前提：只有文本、没有 `\includegraphics` 的幻灯片，树搜索无法改善图文排版。

## 5. 缓存与数据完整性

### 5.1 产物缓存：`scripts/artifact_cache.py`

缓存按内容事实而非任务 ID 寻址，分两层：

```text
原论文 SHA-1 + 提取/论文类型事实 ──► struct/<key>/main.tex
main.tex SHA-1 + 语言/模型/树搜索/配图事实 ──► deck/<key>/{slide_imgs, slides_rendered.pdf, subtitle_w_cursor.txt}
```

缓存条目带 `manifest.json`，可追溯来源任务、字段和值。关键安全策略是“输入不可辨认则不复用”：例如没有 `source_sha1` 或 `main_tex_sha1` 时宁可重算，也不会把两篇未识别输入误当同一内容。

### 5.2 数字人复用保护

`talking_gen.py` 对每页数字人产物不再只看“视频文件存在”。它为人像和音频计算大小与 SHA-1 指纹，写入 `.inputs.json`；任何缺失、损坏或不一致都会重生成。此处规避了最危险的静默错误：新讲稿生成了新音频，但成片仍混入旧数字人视频及其旧音轨。

### 5.3 任务状态和进度

- `job.json`：任务配置、状态、退出码、阶段等持久状态。
- `run.log`：完整子进程输出，是旧任务的进度回退来源。
- `progress.jsonl`：上游的 `progress_report.py` 按行追加结构化事件；环境变量未设置时不生成，从而不改变 CLI 原有行为。
- `web/app.py::read_progress`：优先 JSONL、回退日志正则，并按阶段权重计算单调总进度。
- 前端 `useJobStream`：SSE 断流会指数退避重连，终态停止重连，避免界面“跑完但不出现产物”。

## 6. 模型、环境与外部依赖

| 能力 | 当前默认/实现 | 关键依赖或边界 |
| --- | --- | --- |
| 文本/视觉生成 | `deepseek-flash` 配置 | API 密钥来自环境，不能进入任务文件或 Git。 |
| 语音 | Qwen3-TTS；`speech_gen.py` 也保留 F5 分支 | 默认选 Apache-2.0 的 Qwen3-TTS；参考音频与参考文本必须配对。 |
| ASR/对齐 | Qwen3-ASR + Qwen3-ForcedAligner | 为光标与字幕时间轴服务。 |
| 光标 | GUI-Owl | 使用工具调用格式与 0–1000 归一化坐标解析。 |
| 数字人 | MuseTalk v15 / `musetalk-local` | 外部仓库和权重位于工作区外；单卡串行、需偶数尺寸补丁。 |
| 文本编译/视频 | tectonic、PyMuPDF、ffmpeg | Windows 下不依赖 bash；`merge_video.py` 是 Python 合片替代。 |
| 前端 | React 18、Vite 5、TDesign | `main.tsx` 必须在项目样式前引入 TDesign 全局主题 CSS。 |

上游 `requirements.txt` 仍保留原始依赖痕迹（如 F5、WhisperX、UI-TARS），不能把它单独视为“本项目完整、可运行的锁定环境”。本项目真实运行方式还依赖外置模型路径、环境变量、MuseTalk 环境和 Windows 工具链；部署前应先运行 `scripts/check_env.py` 与相关冒烟脚本确认。

## 8. 关键风险与维护规则

1. **GPU 并发风险**：Web 队列与数字人配置都是按单卡 16GB 设计。并行化必须先做显存实测，不能仅修改 worker 数量。
2. **编码风险**：Windows 默认编码与 UTF-8 不同。主链已在关键写入处显式使用 UTF-8，并通过 `PYTHONUTF8=1` 对齐子进程；新加的文本 I/O 必须保持这一约定。
3. **外部数字人依赖**：MuseTalk 不在 Git 中；其补丁、权重路径与 ffmpeg 可用性必须作为部署清单的一部分。
4. **缓存正确性优先**：缓存键的字段、提取器版本、提示词语义或配图策略变化时，需要更新版本/字段或主动使旧条目失效；不要用“文件存在”替代内容指纹。
5. **任务隔离尚未完成**：服务目前为本机单用户模式（回环监听、共享任务目录）。迁到多人服务器前，需要补用户隔离、鉴权、配额、审计和内网访问策略。
6. **扫描型 PDF**：当前检测但未提供 OCR 主流程；对此类输入应在界面/交付前明确提示用户提供可检索 PDF 或 Word 源文件。
7. **评测子树与生产链不同**：`Paper2Video-main/src/evaluation/` 很大且有独立依赖，不应把评测故障误判为出片主链故障。

## 9. 建议的新接手阅读顺序

1. 阅读 [项目讲解.md](项目讲解.md)，建立产品、论文和本地改造的全局认识。
2. 阅读 [代码改造总览.md](代码改造总览.md) 与 [上游补丁清单.md](上游补丁清单.md)，理解哪些上游差异不能被误覆盖。

4. 阅读 `scripts/paper_ingest.py`、`scripts/paper_figures.py`、`scripts/artifact_cache.py`，理解 PDF/Word 输入为什么能进入 LaTeX 流水线。
5. 阅读 `pipeline.py`，再按阶段进入 `speech_gen.py`、`cursor_gen.py`、`talking_gen.py` 与 `merge_*`。
6. 最后阅读 `web/frontend/src/App.tsx`，它主要是展示后端下发的选项、状态和进度，而非业务规则的来源。
