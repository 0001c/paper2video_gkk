## 已确认的逻辑问题及建议
1. P1 重复提交：App.tsx submit 没有 submitting 状态，开始按钮仅根据已选 job 的 running 禁用。人像上传/音色解析/创建任务响应返回前重复点击可能创建多个任务。建议提交开始立即加锁，按钮显示上传中/创建中，finally 解锁。
2. P1 网络异常无法收敛：doIngest、verifyKey、genVoice、uploadVoice、doRerun 的 fetch 没有 try/catch/finally，网络拒绝会跳过解除 busy 状态。options 初始化失败则静默，用户看到空列表或长期加载。建议统一错误处理和可见的重试入口；cancel 也应检查响应后再提示成功。
3. P1 文件与提取结果竞态：提取 A 时仍可选 B；B 清空 ingest，但 A 晚到的响应会重新写入 ingest，界面显示 B 的名称却用 A 创建任务。建议提取期间禁换文件，或用请求序号/AbortController 拒绝过期响应。
4. P1 提示词被静默覆盖：App.tsx 518、529 的 effect 在模板变化时直接替换已编辑的讲稿/幻灯片提示词。切换类型/语言会丢失手动修改。建议区分未修改模板和用户编辑内容，后者保留草稿或显式提示是否应用新模板。
5. P1 已保存音色试听类型错误：voiceList 含 design/upload，但 genVoice 在 preset 页一律传 kind=preset 及 spec.voice，没有原样使用选中 spec；后端预置生成需要 voice。建议缓存候选直接播放已有 sample_url，新增生成/上传后刷新音色列表；修改描述/语言需使旧试听失效。
6. P1 续跑成本文案不真实：前端 doRerun 固定提示不产生 API 费用，但 pipeline.py stage 2 只在已有讲稿存在且校验通过时复用，否则重新调用模型。建议后端预检可复用性，前端显示实际计划、复用条件和可能成本；不要对所有失败任务都承诺免费。
7. P1 续跑覆盖边界提示过晚：后端 config.result_dir 指向原任务产物目录，前端入队后才提示共享/覆盖。建议入队前明确说明重跑语音/数字人/合片并覆盖原结果，且当前表单修改并不随默认续跑提交。
8. P2 当前任务与新建表单混淆：查看记录只改 jobId，不同步表单；开始按钮禁用由正在查看的 job 决定。查看完成任务时可提交，查看运行任务时不可提交，尽管后端支持串行排队。建议分别管理新任务草稿与查看任务，在 UI 中区分新建、任务详情、任务记录；查看后滚动定位到详情。
9. P2 切换任务残留：useJobStream 在非空 jobId 切换时不清空旧 job，产物 effect 也不立即清空已有列表。新任务响应前可能用新 ID 显示旧进度/产物链接。建议切换时清空或显示加载占位，避免合并旧任务数据。
10. P2 耗时估算忽略明确页数：est 依正文字数推页数且未依赖 slideCount，与用户设置的 4～40 页脱节。建议按目标页数估算，执行时使用实际页数，并在提交按钮旁显示数字人是否实际启用、音色、语言及排队情况。
11. P2 表单体验：两块提示词编辑器默认展开（12/14 行），大量实现术语、阶段 2/3 文案增加操作负担；建议提示词收进高级设置，续跑用具体动作命名，主动作附近列出缺失条件。
12. P2 草稿与连接校验：刷新只恢复凭据/jobId，语言、提示词、页数、文件选择等不能恢复；更改 API key/base 后旧 keyCheck 仍显示成功。建议存可序列化草稿并提示重新选文件，凭据变动立即使旧自检结果失效。
13. P2 可访问性：Dropzone 是可点击 div，没有键盘交互且 input display:none，键盘用户无法使用。建议使用原生按钮/label，补焦点和键盘行为。
