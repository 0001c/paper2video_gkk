# 百炼接入 P3：文字与视觉独立调用

状态：代码实现和离线验证完成；没有真实百炼推理、媒体上传、本地模型加载、服务重启或浏览器视觉验收。模型目录可见、配置合法、协议请求体正确均不等于权限/余额/效果验收。

## 1. 本阶段接通的环节

| 环节 | 角色 | 实际入口 |
| --- | --- | --- |
| PDF/Word正文结构化与截断续写 | text | `scripts/paper_struct.py --model-config` |
| Beamer课件生成、LaTeX编译错误修复 | text | `latex_code_gen_upgrade`、`correcte_error` |
| 课件布局候选的视觉选择 | vision | `improve_layout`、`improve_per_slide` |

`pipeline.py`与`pipeline_light.py`都显式传入角色及任务快照。只构造实际所需角色的配置，单独执行stage 2不要求闲置文字角色的凭据。light入口仍保持原来的无数字人命令行流程，网页审核继续使用主pipeline。

## 2. 连接与参数

- v2文字/视觉不再共用一个全局OpenAI客户端或端点。即使两个角色型号名相同，也分别读取自己的连接URL和角色凭据。
- `role_settings`仅构造安全的运行配置：型号、URL、参数、连接/范围ID、凭据环境变量名和目录上下文上限。实际Key在创建客户端时读取，只传给SDK，不进入配置或缓存指纹。
- 任务子进程只注入当前执行所需的`PAPER2VIDEO_ROLE_<ROLE>_API_KEY`；清除继承的`OPENAI_*`、`DEEPSEEK_*`，包括组织/项目等SDK可能隐式借用的全局参数。缺角色Key时直接失败，不能回退全局Key。
- 本地文字/视觉仍指明确部署的OpenAI兼容服务。空Key的本地服务使用SDK占位Key，不自动加载文字/视觉权重，也不把“本地”误解释成云API。
- `temperature`范围0～2；`max_output_tokens`范围1～131072，映射为兼容协议的`max_tokens`。只有显式填写才覆盖；v2不会借用`PAPER2VIDEO_MAX_TOKENS`。
- 结构化工具未覆盖温度时仍保留算法默认0.2；其他兼容请求未覆盖的参数由服务默认处理。未知手填型号无法离线确认其特殊参数约束。
- 推荐百炼`qwen3.8-flash`、`qwen3.8-max`、`qwen3-vl-plus`显式发送`extra_body.enable_thinking=false`，用于现有非流式课件/讲稿输出。此请求构造已通过SDK模拟传输验证，服务端接受性与当前账户权限仍需后续实测；不向其他兼容服务盲目发送此扩展。

目录保留并仅提取正整数的`context_window`、`max_input_tokens`、`max_output_tokens`。校验已知型号时额外检查输出上限，错误定位到`config.model_config.stages.<role>.parameters.max_output_tokens`。选中角色的限制写入对应脱敏连接快照；CAMEL Agent通过实例参数读取上下文上限，不为不同角色临时改写全局模型窗口。

现有工作空间快照中`qwen3-vl-plus`最大输出32768、上下文262144；`qwen3.8-flash/max`最大输出131072、上下文1000000。仅是该目录快照的信息，不推广到别的连接或自行部署的同名模型。

## 3. 前端与接口

- 沿用现有React/TDesign界面，不新增依赖或页面。面向配置生成任务的用户，以清晰、克制的设置表单为主；文字与视觉各有“请求参数”折叠区、独立标签和清空覆盖入口。
- 两个角色可分别选择本地/API、型号、连接和参数；既支持全API准备阶段，也支持文字API+视觉本地等显式混合。
- 参数进入已有v2草稿白名单与任务快照。新任务草稿、历史任务、审核继续和重跑继续隔离，不把连接Key存入localStorage。
- `GET /api/options`中的`independent_text_vision_connections`与`role_model_parameters`现在为true；后者本阶段仅指文字/视觉参数，TTS语速能力没有顺带开放。
- `POST /api/model-config/validate`不再因两个连接不同或文字/视觉参数非空拒绝请求；其他角色的未实现适配器仍明确拒绝。接口没有新增模型推理自检。
- `POST /api/models`候选条目可包含脱敏`model_info`，前端在已有目录信息下提示型号输出上限。未刷新目录时不能把输入控件上限当成服务端验证。
- 任务`model_config.json`仍只有P1定义的四个顶层字段；目录限制作为`model_connections[id].model_limits[model]`的安全元数据保存，不增加秘密字段。
- `paper_struct.py --model-config <快照路径>`按文字角色执行，结构化与续写共享同一快照；v2不接受另外的`--max-tokens`覆盖。旧命令行参数与旧任务环境路线继续兼容。

## 4. 缓存与兼容

- 结构化缓存指纹增加文字后端事实；课件/讲稿缓存增加文字和视觉后端事实：模式、提供方、型号、参数、连接ID、范围、URL及运行版本。修改视觉配置不使结构化缓存失效，修改文字配置会使结构化及课件缓存失效。
- v2缓存不再借用父进程的全局API base；旧任务缺省的新字段不进入哈希，因此旧结构化/课件缓存键保持不变。
- 逐页课程/审核缓存升级到指纹版本3，使用脱敏模型配置而非整个配置的字符串。范围或参数变化不能误命中成功页；同一次失败恢复仍可复用成功页。
- `ConnectionStore.freeze`深拷贝已有连接快照，避免新任务标注目录限制时改写来源任务的嵌套元数据。重新绑定保留任务已有的实际必需角色，并更新新连接的安全限制信息，但不启动执行。
- 续写测试发现原`CONTINUE_TEMPLATE`中的LaTeX `{document}`被`str.format`当成变量，已经改为模板转义，确保截断续写确实可进入模型调用。

这里只补齐P3文字/视觉切换必须具备的缓存隔离；云音色、媒体模型、时间轴与数字人缓存完整适配仍属P8。
