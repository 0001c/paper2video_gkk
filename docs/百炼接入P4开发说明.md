# 百炼接入 P4 开发说明

## 当前结论

P4主线代码已实施：百炼HTTP流式配音、云音色资源管理、音频/字级时间戳配对缓存，以及前端本地/API切换。验证为离线模拟与构建，不代表真实API权限、费用、音质或生产OSS验收。

全API视频仍未接通：API光标定位留给P5；数字人严格小于20秒的分段和Wan接入留给P6/P7。P4可用组合是“文字/视觉API + 百炼配音/时间戳 + 现有本地光标定位”，实际模式显示mixed，不伪称全API。

可选API ASR仍是明确留项：本次云音色路线不使用本地参考录音作为TTS输入，因此不需要ASR；本地上传音色缺参考文本时仍使用原Qwen3-ASR。本次没有开放fun-asr执行适配器。

## 配音与前端操作

1. 在“管理连接”保存百炼连接，显式填写兼容地址、原生HTTP地址与资源范围。原生地址为北京业务空间的`https://<业务空间>.cn-beijing.maas.aliyuncs.com/api/v1`，也接受北京`https://dashscope.aliyuncs.com/api/v1`。没有原生地址就拒绝云配音，不从兼容URL猜地址，也不需要WebSocket。
2. 在保留现有本地路线的组合中将配音切为API，选择连接和型号；时间轴随之切换为tts_timestamp。配音HTTP适配白名单为cosyvoice-v3.5-plus、cosyvoice-v3.5-flash、cosyvoice-v3-plus、cosyvoice-v3-flash、cosyvoice-v2，语速范围0.5～2。
3. 首次可选cosyvoice-v3-flash的龙安洋系统音色；其他型号需要匹配的专属音色。这里只内置一个有官方时间戳说明的系统音色，不编造跨型号音色兼容表。
4. 注册已有voice_id不会合成，状态是unverified；显式查询云端状态后，仍需主动试音验证时间戳，方可用于视频。试音按钮明确提示可能计费。
5. 本地模式仍用默认/上传参考录音，不接管旧MiMo。新任务和任务自己的审核/续跑模型面板都可切换配音；任务音色不会借用新任务草稿。任务切回本地时可明确选择本地默认参考音色。
6. 模型目录和本地音色目录读取、配置检查、获取已有试听都不生成。创建音色、上传复刻素材和试音只在用户点击对应动作时发生。

音色在此服务中绑定scope_id、原生端点、target_model和resource_id。资源范围仍是受信本机/局域网管理员的声明，并非阿里云账号认证；不支持当成无鉴权公网多租户服务。

## 音色接口

为避免旧`/api/voices/generate`的MiMo请求与百炼请求混淆，P4使用独立`/api/cloud-voices`命名空间；旧路由保持兼容。

| 方法/路径 | 行为 |
| --- | --- |
| GET /api/cloud-voices?connection_id=…&target_model=… | 读取该范围本地资源目录；无推理 |
| POST /api/cloud-voices/register | 严格登记已有专属voice_id；不假装已验证 |
| POST /api/cloud-voices/generate | clone/design，明确consent=true；需要Idempotency-Key |
| POST /api/cloud-voices/{resource_id}/refresh | query_voice，只保存状态、目标型号和合法修改时间，丢弃远端素材链接 |
| POST /api/cloud-voices/{resource_id}/preview | 明确的一次合成试听；需要Idempotency-Key；复刻/注册音色同时验证字级时间戳 |
| GET /api/cloud-voices/{resource_id}/sample | 只读本地归档WAV，不隐式试音 |

登记请求示例（不要传入Key）：

```json
{
  "connection_id": "已保存的百炼连接ID",
  "target_model": "cosyvoice-v3-flash",
  "voice_id": "cosyvoice-v3-flash-p2v-已有专属ID",
  "label": "我的讲解音色"
}
```

本例voice_id只是占位，需要替换成真实匹配型号的ID。任务仅引用`voice: {"kind":"cloud","resource_id":"voice_…"}`，服务端保存非秘密voice_resource快照到model_config.json；后台启动排队任务时保留该音色快照，不偷偷取全局草稿。

创建和试听使用持久化防重账本`jobs/_cloud_voices/registry.json`：同键同输入返回原结果，同键不同输入409；失败/受理不明保存submission_unknown，不自动重新提交。只持久化请求指纹、资源ID与安全结果，Key、Authorization和签名URL不落盘。本阶段不新增云音色删除接口。

## 复刻与设计边界

本地录音上传继续使用现有解码流程；上传完成并不等于上传云端。复刻只接受本服务录音缓存中的16位WAV、采样率至少16kHz、5～60秒且不超过10MiB。这是本项目入口约束，不声称是全部模型的官方最大上限。

CosyVoice复刻的URL要求公网可访问。本次不把百炼临时`oss://`上传机制直接假设为voice-enrollment可用：未得到此接口明确的适用证据，选择服务端私有OSS + 30分钟签名GET。没有OSS配置或SDK时，在记录云提交前明确拒绝；不会把Windows路径或localhost URL发送给百炼。

服务端可选依赖与配置：

```powershell
.venv/Scripts/python.exe -m pip install -r scripts/requirements-bailian-speech.txt
```

- `PAPER2VIDEO_VOICE_OSS_ACCESS_KEY_ID`
- `PAPER2VIDEO_VOICE_OSS_ACCESS_KEY_SECRET`
- `PAPER2VIDEO_VOICE_OSS_ENDPOINT`：如`https://oss-cn-beijing.aliyuncs.com`，使用外网HTTPS端点。
- `PAPER2VIDEO_VOICE_OSS_BUCKET`
- `PAPER2VIDEO_VOICE_OSS_REGION`：如`cn-beijing`。

需自行配置最小权限RAM凭据、私有Bucket及样本自动清理的生命周期。本代码使用OSS V4签名并明确设置对象private；没有自动创建Bucket、公开Bucket或删除云资源。配置留在服务端，不通过浏览器提交，不随v2流水线子进程环境传播。本轮没有安装此可选依赖，也没有进行真实OSS上传。

设计音色可创建与试听，但timestamp_status保持unknown；没有官方充分兼容依据时，禁止用于视频配音，更不会偷偷调用本地ForcedAligner。创建设计音色自带的preview_audio如返回则归档，可直接试听；额外试音仍是一次明确的可能计费动作。

## 音频与时间轴

- 原生HTTP SSE接口为`/services/audio/tts/SpeechSynthesizer`，请求input中明确指定PCM、24kHz、语速和word_timestamp_enabled。Key来自任务TTS角色环境变量，不借用全局OpenAI或百炼Key。
- PCM按服务端指定采样格式写入逐页WAV。收到完成标志、音频与完整字级映射后才认为成功；不读取/保存远端结果签名URL。
- 请求分块最多400字符；合并只在块间加一次0.35秒静音。毫秒转换为秒，偏移按实际样本数计算，而不是按文本长度猜时长。这不是20秒数字人分段。
- `audio/<page>.timing.json`包含原稿SHA、音频SHA、采样格式/数量、原文与规范化索引映射、words和chunk采样偏移；manifest包含模型/范围/音色版本、语速、分块策略与配对文件指纹。
- 复用同时检查WAV、sidecar、manifest、完整原稿映射与非负/单调/不越界的时间戳。缺任一配对产物不算命中；已完成分块可重建页配对而无需再次合成。
- 每个尚未提交的分块先写`.submission.json`；中断后无法核实受理状态时禁止自动重新提交。不要手动删除防重标记来绕过核对。
- cursor_gen在tts_timestamp模式直接读取并校验sidecar，不加载ForcedAligner；光标位置仍可走现有本地GUI-Owl/PDF路线。原本地时间轴缓存键保持兼容。
- 本地取消只停止后续提交及本机子进程；运行中的云配音显示remote_cancel_state=unconfirmed，并提示云端可能继续处理/计费。不声称远程请求已撤销。

严格映射是有意的fail-closed策略：如果供应商把数字/公式等改写为与原稿不等价的时间戳文本，拒绝配对，要求核对讲稿/供应商结果，而不是伪造按字数平均时间轴。

## 验证与下一步

P4离线检查、既有P1/P3回归、前端单元测试和生产构建均为必要合理测试；没有启动真实生成任务、GPU权重、真实云推理/复刻/OSS上传，也没有重启当前服务。浏览器视觉与真实音质尚未验收。

下一阶段P5：接入qwen视觉光标定位白名单解析，替换当前local grounding分派；保持TTS sidecar无本地对齐依赖，并补API光标/本地光标切换回归。可选fun-asr仍是独立留项，需要核实其输入上传与任务协议，不能因为目录出现就开启执行。

P8继续负责任务级共享产物写入所有权、完整入口集成和供应商外部更新音色导致的缓存边界；本次没有递归删除任何共享产物。
