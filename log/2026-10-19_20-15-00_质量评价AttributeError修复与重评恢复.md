## 根因证据与判断边界

- 任务日志先完成 20/20 页实际成片 ASR 与抽帧，随后出现两次成功 HTTP 200，接着发生 AttributeError。
- evaluation 目录保存了本次首轮 `knowledge-15f1…response.json` 的 20 题答题数组；使用原题库、原成片识别与抽帧证据离线调用原 `grade` 可以正常得到 85 分。
- 本次没有证据修正 response、最终 knowledge 报告、rubric 成功缓存，也没有 model_request 内部错误文件；错误集中在第二次答题响应返回之后的提取过程。
- `quality_evaluation.py` 的首轮与证据修正均直接使用 `request(...).get('answers')`；旧版 `qa_evaluation.py` 也有相同代码。`parse_json` 允许 JSON 数组、null 等合法根类型，因此读取 `.get` 会引发 AttributeError。离线替身可复现此路径。
- 旧代码没有保存第二次完整根响应，因此无法据历史文件断言它具体是 null、数组还是其他类型。不得把推断写成已取得的原始响应事实。
- 同类缺口还涉及原文题库响应和逐页 rubric 根响应保存；修复应保留阶段与根类型，方便后续排查。

## 实现原则

- 在提取字段前保存完整模型根响应，显式校验 JSON 对象；根格式错误有限重试，耗尽后清楚报 ValueError，不产生虚假分数。
- 首轮答题、证据修正与旧版评价共用缓存恢复逻辑；旧 `*.response.json` 保存的是答案数组，与新模型返回的根对象必须明确区分。
- 只复用通过原有字段校验的答题缓存；证据修正还必须保持各题选项不变。错误缓存保留诊断但不能让未来重评永久复用坏结果。
- 沿用原计分、逐字证据、图像时间、选项不可变、用户各项通过线与重生成路由。评分语义不变，不改题库/ASR/评价 identity，避免使已付费材料失效。
- 逐页 rubric 的格式重试仍由原 3 次总预算控制，不叠加为 3×3 次。
- 额外本地诊断只记录异常类型、源码文件名、函数和行号，不写入密钥、HTTP 请求、异常完整原文或正文材料。

## 后续维护边界

- `request_object` 的自动格式重试只针对 JSON 根非对象；根合法但字段不合法仍由原验证明确报错。不得宣传为“任意模型格式问题都能自动恢复”。
- 空音频通用证据的派生只适用于已经验证的专用引文；空、伪造或不匹配引文仍拒绝。排版兼容只忽略原有匹配器允许的空白，不忽略字词和标点差异。
- 完整根响应与位置诊断应保留在私有 evaluation/任务目录；错误消息不要泄漏密钥、请求头或异常完整原文。
- QA CLI 只评价而不路由；正式 `/evaluation/run` 会执行配置中的自动路由。以后修复同类问题可先 CLI 得到真实结果，再通过既有接口回填缓存，避免因为格式故障或未知分数误触发昂贵的整套重生成。
