# Paper2Video 项目讲解

> 把一篇论文（PDF / Word）自动变成一段「有幻灯片、有字幕、有真人数字人讲解」的学术演讲视频。
> 本文档是项目的总览讲解，面向需要理解「这个项目是什么、怎么搭起来的、当前做到哪一步」的人。

---

## 一、一句话概括

这是一个 **论文 → 学术演讲视频** 的自动生成工具，技术底座来自论文
[*Paper2Video: Automatic Video Generation from Scientific Papers*](https://arxiv.org/abs/2510.05096)（arXiv 2510.05096v2，
Show Lab, 新加坡国立大学）。本仓库在此基础上完成了两件论文本身没有做的事：

1. **国产化模型替换**：把论文里的所有模型（F5-TTS / UI-TARS / WhisperX / Hallo2 / GPT-4.1 / Gemini）
   全部换成国产开源模型与 DeepSeek API，使其能在 **单张 RTX 5070 Ti 16GB** 上真正跑起来。
2. **工程化落地**：加了一层 Web 界面（上传素材 → 选参数 → 看进度 → 拿成片），
   并支持从 **PDF / Word** 直接输入（论文只支持 LaTeX 源码目录）。

---

## 二、论文在解决什么问题

### 2.1 背景

学术会议普遍要求作者提交 **2~10 分钟**的演讲视频作为论文的配套材料。手工制作一条视频，
需要设计幻灯片、写逐页字幕、逐页录音、剪辑，**平均要花数小时**。

### 2.2 论文的两大贡献

| 贡献 | 内容 |
|---|---|
| **Paper2Video 基准** | 101 篇论文 + 作者录制的演讲视频、幻灯片、演讲者身份元数据，配套 4 项评测指标 |
| **PaperTalker 框架** | 首个多智能体学术演讲视频生成框架，串联幻灯片生成、字幕、光标定位、语音合成、数字人渲染 |

### 2.3 四项评测指标（论文自创，用于衡量「视频讲得怎么样」）

| 指标 | 衡量什么 | 用什么评 |
|---|---|---|
| **Meta Similarity** | 生成的语音/幻灯片/字幕与真人做得多像 | VLM（语音用说话人嵌入算余弦相似度） |
| **PresentArena** | 哪个视频更好（AI vs 真人，双序成对比较） | VideoLLM 当「代理观众」 |
| **PresentQuiz** | 视频多大程度传达了论文知识 | VideoLLM 看视频答选择题，算准确率 |
| **IP Memory** | 视频多大程度让观众记住作者与工作 | VideoLLM 回忆问答 |

> 论文结论：PaperTalker 在 PresentQuiz 上**超过真人视频 10%**，且生成速度提升 **6×**。

### 2.4 PaperTalker 的四条流水线（论文原版）

```
论文 D ──► ① Slide builder   用 LaTeX Beamer 生成幻灯片 + 树搜索视觉选择优化布局
        ──► ② Subtitle builder  VLM 看幻灯片写逐句字幕 + 视觉焦点描述
        ──► ③ Cursor builder   UI-TARS 定位坐标 + WhisperX 时间对齐 → 光标轨迹
        ──► ④ Talker builder   F5-TTS 语音合成 + Hallo2 数字人 → 逐页并联合片
```

其中 ③④ 是**逐页并行**（论文因此需要 8×A6000 48GB），这是它「快」但「贵」的根源。

## 四、本项目的流水线（三层 Stage）

现有流水线分三个阶段，**只有 stage 1 花 API 钱**，其余全走本机 GPU：

| 阶段 | 内容 | 用什么算 | 花钱 |
|---|---|---|---|
| **stage 1** | (LLM) 论文 → Beamer 幻灯片代码 → 编译成 PDF → 转图<br>(VLM) 看幻灯片写讲稿 + 光标描述 | DeepSeek-V4.1-Flash（API） | **是** |
| **stage 2** | Qwen3-TTS 逐页合成音频 + GUI-Owl 定位光标 | 本机 GPU | 否 |
| **stage 3** | 数字人逐页生成 + 拼接 + 烧字幕 | 本机 GPU | 否 |

实测 token 成本（来自 `result/<名字>/token.json`）：一篇论文约 5.6 万 token，**讲稿生成占 76%**，
所以 `--reuse_script`（复用讲稿、只重跑后两步）是省钱主力。

## 五、模型国产化替换（项目最核心的技术工作）

> 完整方案见 `docs/模型替换方案.md`，这里只给结论速览。

论文原版的模型组合在本机 **RTX 5070 Ti 16GB（sm_120，Blackwell）** 上是「死局」：
UI-TARS-7B bf16 要 15GB+ 直接 OOM；Hallo2 锁死 cu118（不含 sm_120 编译目标）架构不支持；
F5-TTS 是 CC-BY-NC 非商用许可证。

替换结果——本地侧从「5 个异构模型、3 套环境、2 个许可证雷」收敛成「2 个模型家族」：

| 模块 | 原模型 | 替换为 | 许可证 | 关键理由 |
|---|---|---|---|---|
| 语音合成 | F5-TTS 0.34B | **Qwen3-TTS-12Hz-1.7B-Base** | Apache-2.0 | 3 秒零样本克隆，当前最主流开源 TTS |
| 光标定位 | UI-TARS-1.5-7B | **GUI-Owl-1.5-4B-Instruct** | MIT | 同为 0-1000 归一化坐标，4.4B 能装下 |
| 转写+对齐 | WhisperX large-v3 | **Qwen3-ASR-0.6B + Qwen3-ForcedAligner-0.6B** | Apache-2.0 | 对齐误差 27.8ms，比 WhisperX 好 67–77% |
| 数字人 | Hallo2 | **LongCat-Video-Avatar-1.5** | MIT | 原生支持 CUDA≥12.8，解掉 sm_120 死结 |
| 音色相似度 | SpeechBrain ECAPA | **CAM++**（3D-Speaker） | Apache-2.0 | 精度与速度双超 ECAPA |
| 语言/视觉（API） | GPT-4.1 / Gemini | **DeepSeek-V4.1-Flash** | 原生图像输入 + 1M 上下文 |
| 视频理解（API） | Gemini-2.5-Flash | **Qwen3.5-Omni-Plus** | DeepSeek 不支持视频，这段换人 |

**显存峰值**从 24GB+ 降到约 10GB（串行分阶段加载）。

> 数字人经历了「Hallo2 → InfiniteTalk → LongCat」两次换型：InfiniteTalk 在 Windows 原生路线的
> fp8 加载会触发 CUDA 扩展 JIT 编译（nvcc 12.6 无 compute_120），最终放弃；LongCat 无需现场编译，
> 只需打一个把 triton 改为惰性导入的纯 Python 补丁（`scripts/patch_longcat.py`）。

### 两个「换 DeepSeek 几乎零改造」的关键事实

1. `wei_utils.get_agent_config()` 有兜底分支 → 传 `--model_name_t deepseek-flash` 即可，
   只需设 `OPENAI_API_BASE` / `OPENAI_API_KEY`，不用改代码。
2. `cursor_gen.py` 本就按 `factor=1000` 的归一化坐标解析，与 GUI-Owl 同源。

### 三条硬约束（踩过坑后写死的）

1. **单卡必须按阶段加载/卸载**：`multiprocessing.Pool` 会让每个 worker 各持一份完整权重，单卡上必须改串行。
2. **项目路径含中文** → 权重放英文目录（`E:\ai-models\`）；`HF_HOME` 必须在 E/F 盘。
3. **许可证雷区**：`tencent/HunyuanVideo-Avatar` 是腾讯社区协议（非商用），商业交付只用 Apache-2.0/MIT。

## 六、H5 可视化改造（Web 界面）

> 完整方案见 `docs/Web可视化方案.md`。改造原则：**只加外壳、不碰算法**。

把命令行流水线包成网页：**上传素材 → 选语言 → 填 API key → 点开始 → 看进度 → 拿成片**。

### 6.1 核心缺口：输入格式

论文入口要求「含 `main.tex` 的 LaTeX 源码目录」，但**使用者的真实输入是 Word 或 PDF**。
因此补了转换层 `scripts/paper_ingest.py`（零成本提取）+ LLM 结构化：

```
.pdf / .docx / .doc / .tex / .zip ──► 提取文本 ──► LLM 结构化 ──► main.tex
```

实测三条结论改变了实现方式：

1. **不用 Office/WPS 的 COM 自动化**——会连到使用者正在运行的 WPS 实例并挂死 2.5 分钟，一律纯 Python。
2. **PDF 提取必须「行合并」**——PDF 会把句子按列宽硬切成半句，需按中英文标点判断句末再合并。
3. **三种格式内容等价，`.pdf` 信噪比最高，优先用**（真实 Word 不用标题样式，heading=0，
   `.docx` 相对 `.pdf` 并无结构优势）。

### 6.2 架构

```
React + Vite + TDesign 前端  ←REST/SSE→  FastAPI 后端  ←子进程→  Paper2Video 流水线
```

- **用子进程而非 import 调用**：显存释放靠进程退出保证；子进程天然支持取消和崩溃隔离。
- **不经 shell 启动**：`Popen(argv, cwd=绝对路径)`，避免 cmd.exe 被拦、MSYS 中文路径失败。
- **单 worker 串行队列**：单卡 16GB 并行必 OOM；只监听 `127.0.0.1`。

### 6.3 关键接口

```
POST /api/jobs                      创建任务（文件 + 配置）
GET  /api/jobs/{id}/events          SSE 实时进度流
POST /api/jobs/{id}/rerun           续跑（只重跑 stage 2/3 + reuse_script → 零 API 费用）
GET  /api/jobs/{id}/pages           逐页素材索引（服务端拼，命名不一致别让前端拼）
POST /api/key/verify                API key 自检（区分欠费/鉴权/网络不通）
```

### 6.4 进度机制

- **P0 零改造**：后端 tail `run.log` + 正则匹配，换算百分比。
- **P1 结构化**：流水线写 `progress.jsonl`（一行一 JSON，默认不生效、绝不抛异常、只追加），
  后端优先读它、回落日志。可做「每页一个状态点」的细粒度展示。

## 七、音色方案（MiMo 造音色 + 本地克隆）

> 完整方案见 `docs/音色方案.md`。一句话：**云端只造一次音色，逐页仍本地 Qwen3-TTS 克隆**。

| 接法 | 说明 | 结论 |
|---|---|---|
| 用 MiMo 逐页合成 | 云端、14 次调用、限时免费不可依赖 | ✗ |
| **用 MiMo 生成一段音色样本，逐页本地克隆** | **1 次云端调用 + 本地合成** | ✅ 推荐 |

要点：

- 音色一次定下 → 全片一致；免费期结束/断网/无 key 都不影响出片。
- **参考文本必须由我们给定**（写死在 `scripts/mimo_voice.py` 的 `REF_TEXTS`），
  不能用 `optimize_text_preview=True`，否则 ref_text 失控、只能靠 ASR 转写（而 ASR 本项目已知会转错）。
- **已生成的音色不需要 key**（缓存命中直接可用）→ 攒下的音色资产长期有效。
- 任何失败都回落内置音色，且回落原因会进响应与 `run.log`（`[voice]` 行），**不阻断任务**。

## 九、部署目标与迁移约束

**本机（Windows + RTX 5070 Ti 16GB）是开发环境，导师演示通过后会搬到学校 Linux 服务器。**

迁移时要守住的几条（否则「英文演示正常、中文演示炸了」这类问题会在演示当天才暴露）：

1. **中文字幕字体不能硬编码 Windows 字体**——已改为按平台解析（`_cjk_subtitle_font()`，
   Linux 用 Noto Sans CJK），服务器需装 `fonts-noto-cjk`。
2. **权重/缓存路径不要出现盘符**——全走环境变量 + 默认值。
3. **GPU 档位不要写死**——用 `talking_config` 的档位抽象（`local-16g` / `server-8xa6000`）。
4. **多人使用要补四件事**：任务按人隔离、排队可见、按人统计 token、只监听内网。
5. **推荐 Docker 部署**：中文字体必须进镜像，权重几十 GB 用挂载卷。

## 附：项目里最值得记住的几条「血泪教训」

1. **`--if_tree_search` 界面上可开、默认关**：它是「幻灯片布局微调」——编译后挑出有 Overfull 溢出的页，每页生成 4 个缩放候选拼成 2×2 对比图，让 VLM 选一个（宽度 4、深度 1 的束搜索）。默认关是因为**成本**（每张溢出页多 1 次带图 VLM 调用 + 4 次编译渲染），不是因为它会崩：早先记的 `NameError` 来自上游 `pipeline.py` 的 `else` 分支引用了被注释掉的 `latex_code_gen`，**那个分支已被我们合并掉**（2026-09-19 用 symtable 复核，调用链无未定义引用）。
2. **DeepSeek 是推理模型**：`max_tokens` 给小了会返回空 `content`（token 全被 reasoning 吃掉）且**不报错**，要读 `finish_reason`。
3. **MuseTalk 偶数尺寸补丁**：人脸裁框为奇数时 libx264 拒绝编码，产物 0 字节，但上游照样打印「result is save」——症状极具误导性。
4. **日志编码必须统一 UTF-8**：子进程默认按 GBK 输出会污染 `run.log`，界面乱码 + 日志解析正则命中 0 条（不报错）。
5. **测试清理只删「进入前后快照的差集」**，绝不按名字前缀批量删共享目录——曾因此误删使用者正在运行的任务。
